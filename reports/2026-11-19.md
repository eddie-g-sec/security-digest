# Security Digest — 2026-11-19

## Cloud Security

No entry in today’s formal feed is CISA KEV-confirmed, so the most urgent item is the highest-impact critical: Dokploy **CVE-2026-129316** (CVSS 9.9). A user with read access to any Dokploy service can abuse WebSocket handlers to target unrelated containers, obtain a root shell in the Dokploy panel container, read other tenants’ logs/statistics, and use the mounted Docker socket to compromise the host. Patch Dokploy to 0.31.0 immediately; also queue **CVE-2026-129989** (9.9) and **CVE-2026-129990** (8.3), both fixed in 0.31.1.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-68903 (CVSS 7.7 HIGH)
**Summary:** LLMKube before 0.9.0 lets the ModelReconciler accept arbitrary absolute paths and `file://` URIs in `Model.spec.source` without restricting them to approved roots. A namespace user who can create or update `Model` and `InferenceService` resources can cause the controller to open an attacker-selected file or mount an attacker-selected node file when `modelCache.enabled` is enabled, which is the default.

**Affected Features / Interoperability:** LLMKube operator `ModelReconciler`, `copyLocalModel`, `HostPathVolumeSource`, and the default `modelCache` feature. This can expose controller-pod or node files and copy attacker-selected content into model storage; downstream model-serving integrity and node file confidentiality are at risk.

**Source:** https://github.com/defilantech/LLMKube/commit/ec2647fd4557962a971a1bc9435790b8e77ce961 ; https://github.com/defilantech/LLMKube/pull/981 ; https://github.com/defilantech/LLMKube/releases/tag/v0.9.0

**Actions:**
- Fix: Upgrade to LLMKube v0.9.0.
- Workaround: Enforce admission policy rejecting `Model.spec.source` absolute paths and `file://` URIs outside approved roots; restrict RBAC for creating/updating `Model` and `InferenceService`; disable `modelCache` if not required.
- Tradeoff: Breaks legitimate local/file model sources and may reduce model caching/performance.

#### Kubernetes — CVE-2026-132239 (CVSS 7.6 HIGH)
**Summary:** JetBrains TeamCity before 2026.1.3 and 2025.11.7 has missing authorization in the Kubernetes integration, allowing project viewers to use stored credentials. This is an authenticated, role-based exposure rather than an unauthenticated network attack.

**Affected Features / Interoperability:** TeamCity Kubernetes integration and stored Kubernetes credentials. Project viewers may be able to use credentials intended for deployment/integration actions, affecting Kubernetes access boundaries and CI/CD isolation.

**Source:** https://www.jetbrains.com/privacy-security/issues-fixed/

**Actions:**
- Fix: Upgrade to TeamCity 2026.1.3 or 2025.11.7.
- Workaround: Remove stored Kubernetes credentials from projects with untrusted viewers; restrict project viewer membership; audit credential use.
- Tradeoff: Reduces CI visibility/access and may require credential re-provisioning.

#### Kubernetes — CVE-2026-61581 (CVSS 7.4 HIGH)
**Summary:** Prior to `datadog-apm-inject` 0.66.0, the Datadog Single Step Instrumentation injector stores helper tooling in a predictable host directory. On Linux or Kubernetes systems with SSI enabled and at least one Java service instrumented through SSI, a local unprivileged attacker with shell access to the same host can influence that tooling and execute code with the privileges of the instrumented Java service.

**Affected Features / Interoperability:** Datadog Single Step Instrumentation, `datadog-apm-inject`, and Java services instrumented through SSI. Services using `dd-java-agent` without SSI and non-Java runtimes are not affected. Downstream impact is local privilege escalation into the instrumented Java service context.

**Source:** https://github.com/DataDog/datadog-agent/pull/52881 ; https://github.com/DataDog/datadog-agent/security/advisories/GHSA-h8qx-4jh5-pf43 ; https://github.com/DataDog/dd-apm-inject/releases/tag/v0.66.0

**Actions:**
- Fix: Upgrade `datadog-apm-inject` to 0.66.0.
- Workaround: Disable SSI for Java services until patched; restrict local shell access to hosts running SSI.
- Tradeoff: Loses auto-instrumentation/APM for Java services.

#### Kubernetes — CVE-2026-132896 (CVSS 7.2 HIGH)
**Summary:** JetBrains TeamCity before 2026.2 and 2026.1.4 allows remote code execution via Kubernetes Executor settings. Exploitation requires the ability to influence or configure those settings.

**Affected Features / Interoperability:** TeamCity Kubernetes Executor configuration. Downstream CI/CD build execution and the Kubernetes clusters used by the executor may be exposed to attacker-controlled code execution.

**Source:** https://www.jetbrains.com/privacy-security/issues-fixed/

**Actions:**
- Fix: Upgrade to TeamCity 2026.2 or 2026.1.4.
- Workaround: Restrict who can edit Kubernetes Executor settings; disable Kubernetes Executor if not needed.
- Tradeoff: Impacts CI builds that rely on Kubernetes Executor.

#### Kubernetes — CVE-2026-133173 (CVSS 6.5 MEDIUM)
**Summary:** WatchAlert 2.0.0 through 3.9.20 contains an insecure direct object reference in `/api/w8t/datasource/dataSourceGet` because lookups omit `tenant_id` filtering. An authenticated tenant member with datasource view permission can request another tenant’s datasource ID and obtain basic auth passwords, AWS and Alibaba Cloud keys, and Kubernetes kubeconfigs.

**Affected Features / Interoperability:** WatchAlert datasource API and tenant isolation. Exposed downstream assets include cloud credentials and Kubernetes kubeconfigs, so cross-tenant access can lead to cloud and cluster compromise.

**Source:** https://github.com/opsre/WatchAlert ; https://github.com/opsre/WatchAlert/blob/v3.9.20/internal/repo/datasource.go#L63-L65 ; https://github.com/opsre/WatchAlert/commit/ae8c1af20b4f5b02b823482e4bf7d53eafeef369

**Actions:**
- Fix: No patched release version stated in provided data; review referenced commit `ae8c1af20b4f5b02b823482e4bf7d53eafeef369`.
- Workaround: Restrict datasource view permission; enforce tenant filtering at the API gateway; rotate any potentially exposed cloud keys and kubeconfigs.
- Tradeoff: Reduces tenant member access to datasource views.

#### Kubernetes — CVE-2026-132947 (CVSS 6.1 MEDIUM)
**Summary:** JetBrains TeamCity before 2026.2 is vulnerable to reflected XSS in the Kubernetes cloud profile namespace and deployment choosers. An attacker can attempt to execute script in a victim’s TeamCity UI session through crafted input.

**Affected Features / Interoperability:** TeamCity Kubernetes cloud profile UI, specifically namespace and deployment chooser views. Downstream impact depends on TeamCity session privileges and could affect CI/CD administration if an admin is targeted.

**Source:** https://www.jetbrains.com/privacy-security/issues-fixed/

**Actions:**
- Fix: Upgrade to TeamCity 2026.2.
- Workaround: Restrict TeamCity UI access to trusted users; apply input sanitization or reverse-proxy filtering if available.
- Tradeoff: Reduces UI access; filtering may break legitimate namespace/deployment names.

#### Docker — CVE-2026-129316 (CVSS 9.9 CRITICAL)
**Summary:** Dokploy 0.29.13 through 0.31.0 has Docker terminal, container-log, and monitoring WebSocket handlers that accept a caller-controlled `serviceId` as authorization but do not consistently bind the requested `containerId` or `appName` to that service. A member with read access to any service can target unrelated containers, obtain a root shell in the Dokploy panel container, read other tenants’ logs and statistics, and use the mounted Docker socket to compromise the host.

**Affected Features / Interoperability:** Dokploy WebSocket handlers for terminal, container logs, and monitoring; service-level authorization; Docker socket access. Cross-tenant container access and host compromise are the main downstream risks.

**Source:** https://github.com/Dokploy/dokploy/commit/2555b8d91e88b9071a7d6afed84c0ff3b4a3838d ; https://github.com/Dokploy/dokploy/commit/99e4f1c8dc62510b8abd46bd7fd359d6ad61075e ; https://github.com/Dokploy/dokploy/commit/9f6e82abf62ec1cdeb6d0adf7eb8f2fa2fbb076a

**Actions:**
- Fix: Upgrade to Dokploy 0.31.0.
- Workaround: Restrict Dokploy membership/read access; disable terminal/log/monitoring WebSocket features if not needed; remove the Docker socket mount where operationally possible.
- Tradeoff: Disabling features breaks remote terminal/log/monitoring; removing the Docker socket breaks Docker management.

#### Docker — CVE-2026-129989 (CVSS 9.9 CRITICAL)
**Summary:** Dokploy prior to 0.31.1 lets the Nixpacks `publishDirectory` build setting accept shell metacharacters and interpolates it into a `docker cp` command executed through `child_process.exec`. An authenticated user with access to an application can execute arbitrary commands on the Dokploy host when triggering a Nixpacks deployment, leading to host compromise through the privileged Docker environment.

**Affected Features / Interoperability:** Dokploy Nixpacks build configuration and deployment execution. Host compromise can affect all containers and services managed by the Dokploy instance.

**Source:** https://github.com/Dokploy/dokploy/commit/2cd86b2447daba8fefec1272718d40463e18d6a3 ; https://github.com/Dokploy/dokploy/pull/5911 ; https://github.com/Dokploy/dokploy/releases/tag/v0.31.1

**Actions:**
- Fix: Upgrade to Dokploy 0.31.1.
- Workaround: Restrict application deployment access; disallow Nixpacks or sanitize `publishDirectory`; run Dokploy with least-privileged Docker access.
- Tradeoff: Blocks Nixpacks deployments or reduces build flexibility.

#### Docker — CVE-2026-129990 (CVSS 8.3 HIGH)
**Summary:** Dokploy prior to 0.31.1 only authentication-protects every `network.*` procedure and does not require the Docker permission. A standard member can list, inspect, create, import, recreate, resynchronize, and delete Docker networks, and create/import operations can target an unchecked `serverId`.

**Affected Features / Interoperability:** Dokploy Docker network management procedures. A standard member can disrupt service connectivity or alter network configuration; unchecked `serverId` handling may affect other managed servers.

**Source:** https://github.com/Dokploy/dokploy/commit/b4cc3db217a02c5cf58b906a7f3508f4b576d670 ; https://github.com/Dokploy/dokploy/pull/5967 ; https://github.com/Dokploy/dokploy/releases/tag/v0.31.1

**Actions:**
- Fix: Upgrade to Dokploy 0.31.1.
- Workaround: Restrict standard member roles; audit Docker networks; enforce a `serverId` allowlist at the API layer.
- Tradeoff: Reduces member network management and may require admin intervention.

#### Docker — CVE-2026-132243 (CVSS 7.6 HIGH)
**Summary:** JetBrains TeamCity before 2026.1.3 and 2025.11.7 is vulnerable to stored XSS on the Docker Container Info tab. An attacker who can store malicious content may execute script in a victim’s TeamCity UI session.

**Affected Features / Interoperability:** TeamCity Docker Container Info tab. Downstream impact depends on the victim’s TeamCity privileges and could affect CI/CD administration.

**Source:** https://www.jetbrains.com/privacy-security/issues-fixed/

**Actions:**

- Tradeoff: Reduces UI access; filtering may break container info display.

#### Docker — CVE-2026-130767 (CVSS 6.4 MEDIUM)
**Summary:** Obot 0.9.0 before 0.27.0 contains a command injection vulnerability that allows authenticated users to execute shell commands by embedding an EOF line in file-type MCP server configuration values. Attackers can terminate the heredoc in the generated init container script to run commands, modify the MCP server files volume, and reach services on Obot’s Docker network.

**Affected Features / Interoperability:** Obot MCP server configuration, generated init container scripts, and the MCP server files volume. Downstream reachability includes services on the Obot Docker network.

**Source:** https://github.com/obot-platform/obot/security/advisories/GHSA-2mfp-9vv3-q737

**Actions:**
- Fix: Upgrade to Obot 0.27.0.
- Workaround: Restrict MCP server configuration creation to trusted admins; validate file-type config values for heredoc terminators.
- Tradeoff: Reduces self-service MCP configuration.

#### Docker — CVE-2026-129291 (CVSS UNSCORED — severity not provided)
**Summary:** PHP-FPM has an epoll use-after-free that can lead to local privilege escalation when `catch_workers_output` is enabled and the epoll event backend is used. The master can close a worker’s output pipe without removing the associated event, and delayed cleanup can free the worker record while its epoll registration is still active; a local attacker who can execute PHP code in an FPM worker can crash the master or execute code with its privileges, commonly root. `catch_workers_output` is disabled by default.

**Affected Features / Interoperability:** PHP-FPM master/worker process management, `catch_workers_output`, and the epoll event backend. Downstream impact is local privilege escalation from a PHP execution context to the FPM master’s privileges.

**Source:** https://github.com/php/php-src/security/advisories/GHSA-jm4m-qfqx-967m

**Actions:**
- Fix: No patched version stated in provided data; see GHSA-jm4m-qfqx-967m.
- Workaround: Keep `catch_workers_output` disabled; use a non-epoll event backend if feasible; restrict the ability to execute PHP in FPM workers.
- Tradeoff: Disabling `catch_workers_output` loses worker output in the error log; changing the event backend may affect performance.

#### Docker — CVE-2026-77295 (CVSS UNSCORED — severity not provided)
**Summary:** MyMangaDB prior to 2.7.2 has an unauthenticated `/api/v1/database/export` handler that returns a ZIP containing the live SQLite database and cover-image library. The database includes the users table and `hashed_password` values, allowing a remote attacker to obtain all application data and conduct offline password attacks without a session or token.

**Affected Features / Interoperability:** MyMangaDB database export endpoint and SQLite database contents. Exposed data includes user password hashes and application data.

**Source:** https://github.com/FabianRolfMatthiasNoll/MyMangaDB/commit/2ad34ea785c01d096b38a01420d56fc5a1078db4 ; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/releases/tag/v2.7.2 ; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/security/advisories/GHSA-66wj-vwff-vp3p

**Actions:**
- Fix: Upgrade to MyMangaDB 2.7.2.
- Workaround: Block `/api/v1/database/export` at the reverse proxy; restrict network access to trusted users.
- Tradeoff: Breaks the database export feature.

#### Docker — CVE-2026-77296 (CVSS UNSCORED — severity not provided)
**Summary:** MyMangaDB prior to 2.7.2 has an unauthenticated `/api/v1/images/manga/save` handler that accepts a client-controlled filename and joins it to `IMAGE_SAVE_PATH` without confining the result. Traversal sequences can escape the image directory and overwrite process-writable files, including `DATABASE_PATH` for the live SQLite database, while the client-supplied image content type does not validate the uploaded bytes.

**Affected Features / Interoperability:** MyMangaDB image save endpoint, filesystem path handling, and SQLite database file. Downstream impact includes arbitrary file overwrite within process-writable paths and potential database corruption or replacement.

**Source:** https://github.com/FabianRolfMatthiasNoll/MyMangaDB/commit/2ad34ea785c01d096b38a01420d56fc5a1078db4 ; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/releases/tag/v2.7.2 ; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/security/advisories/GHSA-66h5-6vhv-5w76

**Actions:**
- Fix: Upgrade to MyMangaDB 2.7.2.
- Workaround: Block `/api/v1/images/manga/save` or validate filenames at the reverse proxy; restrict process write permissions.
- Tradeoff: Breaks the image save/upload feature.
