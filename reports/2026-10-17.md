# Security Digest — 2026-10-17

## Database

The most urgent issue is CVE-2026-85746 in MariaDB (a MySQL fork), a critical memory corruption vulnerability (CVSS 9.9) allowing low-privileged remote attackers to execute code via crafted GIS objects, affecting healthcare systems using MariaDB for clinical data storage. This vulnerability is actively exploited and requires immediate patching to versions 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, or 13.0.2.

### Formal Vulnerabilities

#### MariaDB — CVE-2026-85746 (CVSS 9.9 CRITICAL)
**Summary:** Memory corruption in ST_AsText GIS function allows low-privileged remote attackers to execute code via crafted GeometryCollections. Requires no authentication and is network-reachable.

**Affected Features / Interoperability:** GIS functions (ST_AsText), potentially impacting spatial data processing in healthcare applications. Replication and client drivers using GIS features may be affected.

**Source:** https://github.com/MariaDB/server/commit/5c04ca5524385356ff7cf84974a7d491974c1f85

**Actions:**
- Fix: Upgrade to patched versions (10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, 13.0.2)
- Workaround: Disable ST_AsText function if not required
- Tradeoff: Loss of GIS functionality if disabled

#### MariaDB — CVE-2026-85748 (CVSS 9.9 CRITICAL)
**Summary:** Use-after-free in SYS_REFCURSOR handling allows low-privileged attackers to execute code by opening many cursors. Network-reachable with low privileges.

**Affected Features / Interoperability:** Cursor management in stored procedures, potentially affecting batch processing and ETL pipelines in healthcare data workflows.

**Source:** https://github.com/MariaDB/server/releases/tag/mariadb-12.3.3

**Actions:**
- Fix: Upgrade to versions 12.3.3 or 13.0.2
- Workaround: Restrict cursor usage in applications
- Tradeoff: Reduced flexibility in stored procedure design

#### MariaDB — CVE-2026-92262 (CVSS 9.9 CRITICAL)
**Summary:** Bypass of table-name encoding via #mysql50# prefix allows attackers to access files and execute code. Requires low privileges and is network-reachable.

**Affected Features / Interoperability:** Table naming conventions, potentially impacting data integrity and access controls in healthcare databases.

**Source:** https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19

**Actions:**
- Fix: Upgrade to patched versions
- Workaround: Avoid using #mysql50# prefix in table names
- Tradeoff: May require schema modifications

## Cloud Security

The most urgent item is **CVE-2026-77459** in Argo CD (Kubernetes) with a CVSS score of 9.9, which allows a user who can write to an Application’s Git repository to create a malicious PostDelete hook that bypasses project authorization checks and can delete cluster-scoped resources or persistent hook objects, potentially leading to unauthorized cluster-wide disruption.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-77459 (CVSS 9.9 CRITICAL)
**Summary:** Argo CD versions 2.10.0 through 3.3.15, 3.4.10, 3.5.4, and 3.6.0-rc2 create PostDelete resource hooks without applying the AppProject destination and resource authorization checks used during normal synchronization. An attacker with write access to an Application’s Git repository can inject a delete hook targeting a forbidden namespace, server, group, kind, or resource name; when the Application is deleted, the controller creates the resource using its cluster credentials.  
**Affected Features / Interoperability:** Argo CD controller’s hook processing, cluster-scoped resource management, namespaced allow/deny lists, persistent hook objects, and secondary objects created by hook Jobs.  
**Source:**  
- https://github.com/argoproj/argo-cd/commit/1149cdc6e932208c4402183cc3d7b7485239940c  
- https://github.com/argoproj/argo-cd/commit/4bc8085b0a6d2296b849539d3d09fc7be7a4a511  
- https://github.com/argoproj/argo-cd/commit/7f0a05834b05103d69d7c150e1ee36541b314696  
- https://github.com/argoproj/argo-cd/commit/d5dd7019ee65be8895133fe4df554e28074242c4  
- https://github.com/argoproj/argo-cd/releases/tag/v3.3.15  
**Actions:**  
- Fix: Upgrade to Argo CD 3.3.15, 3.4.10, 3.5.4, or 3.6.0-rc2.  
- Workaround: Restrict write access to Application Git repositories and audit PostDelete hook usage.  
- Tradeoff: Limits developer ability to self‑service Application changes and may require stricter repo controls.

**Affected Features / Interoperability:** KEDA operator, Vault integration, ServiceAccount token usage, Secret access, and any workloads relying on KEDA‑driven autoscaling.  
**Source:**

- https://github.com/kedacore/keda/security/advisories/GHSA-637c-6jxx-4rwm

- Workaround: Disable or restrict creation of TriggerAuthentication/ScaledObject resources, or enforce strict Vault endpoint allow‑lists.  
- Tradeoff: Loss of dynamic Vault‑based autoscaling and increased operational overhead for manual secret management.
