# Security Digest — 2026-10-29

## Cloud Security

The cloud security landscape this period is dominated by critical vulnerabilities in container orchestration and management tools, with the highest-severity issue being a CVSS 9.9 path traversal in Argo CD (CVE-2026-113672) that allows unauthenticated attackers to read sensitive files, including service-account tokens and private keys, from the repo-server. Additionally, multiple critical flaws in Docker-related tools—such as LocalStack (CVE-2025-65200), Part-DB (CVE-2026-54630), and Dockhand (CVE-2026-57169)—expose container environments to unauthenticated remote code execution and unauthorized terminal access, demanding immediate patching and mitigation.

### Formal Vulnerabilities

#### [Kubernetes] — CVE-2026-113672 (CVSS 9.9 CRITICAL)
**Summary:** This vulnerability is a path traversal flaw in Argo CD's repo-server `.jsonnet` file importer, which fails to confine imports to the repository root. An unauthenticated attacker with network access can exploit this via absolute paths, parent-directory traversal, or repository symlinks to read arbitrary files readable by the repo-server, such as projected service-account tokens, mounted private keys, and environment variables.
**Affected Features / Interoperability:** Impacts the Argo CD repo-server's `.jsonnet` evaluation engine and file import mechanisms. A successful exploit allows exposure of Git repository credentials, Kubernetes service account tokens, and host environment variables, potentially leading to full cluster compromise or CI/CD pipeline hijacking.
**Source:**
- https://argo-cd.readthedocs.io/en/stable/user-guide/tool_detection/#disable-built-in-tools
- https://github.com/argoproj/argo-cd/commit/27471d524958878e7acc5131fb466b292079cd05
- https://github.com/argoproj/argo-cd/pull/561
**Actions:**
- **Fix:** Upgrade to Argo CD version 3.3.15, 3.4.10, 3.5.4, or 3.6.0-rc2 or later, where import confinement has been enforced.
- **Workaround:** Disable the built-in `.jsonnet` evaluation/importer tool in the Argo CD repo-server if it is not actively required for GitOps workflows.
- **Tradeoff:** Disabling the tool will break any automated GitOps pipelines that rely on server-side `.jsonnet` or `importstr` rendering within the repo-server.

#### [Kubernetes] — CVE-2026-59185 (CVSS 8.5 HIGH)
**Summary:** Identrail's machine identity platform contains an authorization bypass in its GitHub connection completion endpoint. The endpoint accepts an `installation_id` from the request body or header without verifying that the installation belongs to the caller's workspace, allowing an attacker to link an arbitrary GitHub installation to a victim's project.
**Affected Features / Interoperability:** Affects the GitHub OIDC integration and workspace project binding within the Identrail platform. This could allow an attacker to hijack machine identity trust relationships, intercept GitHub Actions identity tokens, or gain unauthorized access to linked cloud infrastructure via compromised OIDC configurations.
**Source:**
- https://github.com/identrail/identrail/commit/835e40517509d6ef5405c27fbf14f579bedff0e7
- https://github.com/identrail/identrail/releases/tag/v1.0.2
- https://github.com/identrail/identrail/security/advisories/GHSA-cp3j-m783-3ph5
**Actions:**
- **Fix:** Upgrade Identrail to version 1.0.2 or later.
- **Workaround:** Restrict network access to the Identrail API endpoints and enforce strict validation of GitHub installation IDs in upstream proxy rules if patching is delayed.
- **Tradeoff:** No significant tradeoff noted beyond temporary administrative overhead of network restrictions.

#### [Kubernetes] — CVE-2026-87354 (CVSS 4.3 MEDIUM)
**Summary:** A medium-severity vulnerability in the Oracle TimesTen In-Memory Database Kubernetes Operator allows a low-privileged attacker with network access via HTTPS to perform unauthorized read access to a subset of database data.
**Affected Features / Interoperability:** Impacts the Oracle TimesTen Kubernetes Operator's network listener and authentication mechanisms. Exploitation can lead to unauthorized data reads from in-memory database instances running in Kubernetes, potentially exposing sensitive business data or credentials stored in TimesTen tables.
**Source:**
- https://www.oracle.com/security-alerts/cpuoct2026.html
**Actions:**
- **Fix:** Apply the patch released in Oracle TimesTen versions 22.1.40.0 or later, or 26.1.1.2.0 or later, as detailed in the Oracle CPU of October 2026.
- **Workaround:** Restrict network access to the TimesTen operator's HTTPS ports to only authorized Kubernetes service accounts or pods.
- **Tradeoff:** Restricting network access may prevent legitimate database clients in other namespaces or pods from querying the database, requiring careful network policy tuning.

#### [Kubernetes] — CVE-2026-103506 (CVSS UNSCORED)
**Summary:** An authenticated Grafana user can read sensitive SSO client secrets and modify instance-wide SSO settings without the required administrative permissions due to a missing authorization check. This affects Grafana OSS and Enterprise 13.2 installations where the experimental `kubernetesSsoSettingsApi` feature toggle is enabled.
**Affected Features / Interoperability:** Impacts Grafana's Kubernetes SSO integration settings and the experimental Kubernetes SSO settings API. A successful exploit can expose SSO client secrets, leading to identity provider compromise, and allow unauthorized modification of authentication settings, disrupting user logins and dashboard access control.
**Source:**
- https://grafana.com/security/security-advisories/cve-2026-103506
**Actions:**
- **Fix:** Disable the experimental `kubernetesSsoSettingsApi` feature toggle in Grafana configuration, or apply the official authorization patch when released by Grafana.
- **Workaround:** Ensure the `kubernetesSsoSettingsApi` feature toggle remains disabled (as it is by default) in all Grafana OSS and Enterprise 13.2 deployments.
- **Tradeoff:** If the feature is currently enabled and required, disabling it will remove the ability to manage Kubernetes SSO settings via the Grafana UI/API, forcing administrators to use alternative configuration methods.

#### [Docker] — CVE-2025-65200 (CVSS 9.6 CRITICAL)
**Summary:** LocalStack version 4.9.2 contains a critical remote code execution vulnerability. An attacker can execute arbitrary code by hosting a malicious script on a web-accessible URL and passing it to the `_localstack/cloudformation/deploy` endpoint via the `templateURL` parameter, which executes the hosted content within the Docker container context.
**Affected Features / Interoperability:** Impacts the AWS CloudFormation local deployment engine within LocalStack. A successful exploit allows arbitrary code execution inside the LocalStack container, which can lead to host compromise if sensitive mounts or container privileges are present, and can disrupt local cloud simulation and testing pipelines.
**Source:**
- http://localstack.com
- https://cyberroute.github.io/post/2025-12-11-localstack-hack/
- https://github.com/localstack/localstack/blob/aba1ee84592d76f0a88dd286fcd83b65080e31ac/localstack-core/localstack/services/cloudformation/deploy_ui.py
**Actions:**
- **Fix:** Upgrade LocalStack to a patched version (later than 4.9.2) that validates and sanitizes template URLs.
- **Workaround:** Restrict outbound network access from the LocalStack container and disable the CloudFormation deploy UI/API endpoint if local templates are the only use case.
- **Tradeoff:** Disabling the deploy endpoint or blocking outbound network access will prevent the loading of external CloudFormation templates, limiting dynamic or multi-file template deployment.

#### [Docker] — CVE-2026-54630 (CVSS 9.6 CRITICAL)
**Summary:** Part-DB, an open-source electronic component inventory management system, is vulnerable to arbitrary file upload and execution via crafted `.phar` files. Prior to version 2.12.1, the attachment upload handler uses client-supplied extensions and fails to block the `phar` extension, allowing attackers to upload executable PHP archive files to the publicly served media directory.
**Affected Features / Interoperability:** Impacts the file attachment upload mechanism and media serving directory in Part-DB. Successful exploitation allows remote code execution on the web server when a crafted `.phar` file is accessed or processed by PHP, potentially leading to full server compromise and database exfiltration.
