# Security Digest — 2026-11-14

## Cloud Security

The most pressing issue is a critical privilege escalation in OpsTree BuildPiper (CVE‑2026‑127073) that lets authenticated project users gain Kubernetes cluster‑admin rights via the Additional Manifest feature, enabling full control of clusters and all associated workloads and secrets.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-127073 (CVSS 9.9 CRITICAL)

**Summary:** An authenticated project user can abuse BuildPiper’s Additional Manifest feature to create a ClusterRoleBinding that grants cluster‑admin rights, giving full control over all workloads, secrets, and cluster resources.

**Affected Features / Interoperability:** BuildPiper’s Additional Manifest feature, pipeline application of manifests with cluster‑wide credentials, ClusterRoleBinding creation, service accounts, and downstream workloads and secrets.

**Source:** 
- https://gist.github.com/neelkotnis/7bc715e190e5be2c2fc5be15c4035ce7  
- https probably buildpiper.io  
- https://www.vulncheck.com/advisories/opstree-buildpiper-before-2.7.0-privilege-escalation-via-additional-manifest

**Actions:**
- **Fix:** Upgrade BuildPiper to version 2.7.0 or later.
- **Workaround:** Restrict the Additional Manifest feature, enforce strict RBAC policies, and monitor for unexpected ClusterRoleBinding creation.
- **Tradeoff:** Limiting Additional Manifest usage may hinder legiti‑mate automation; monitoring may generate noise.

#### Kubernetes — CVE-2026-127080 (CVSS 9.9 CRITICAL)

**Summary:** Authenticated deploy users can define arbitrary hostPath volumes (including root “/”) without policy checks, breaking container isolation and enabling node‑level compromise.

**Affected Features / Interoperability:** BuildPiper’s hostPath volume definition, worker node mounting, container runtime isolation, and downstream node/cluster security.

**Source:** 
- https://gist.github.com/neelkotnis/b8c1cf47f829c28086fe78d8187eb938  
- https://www.buildpiper.io/  
- https://www.vulncheck.com/advisories/opstree-buildpiper-before-2.7.0-container-escape-via-unrestricted-hostpath-volumes

**Actions:**
- **Fix:** Upgrade BuildP. to 2.7.0+.
- **Workaround:** Disable hostPath volumes, enforce node‑level restrictions, and use volume snapshots.
- **Tradeoff:** Disabling hostPath may limit legitimate host directory access.

#### Kubernetes — CVE-2026-92982 (CVSS 8.5 HIGH)

**Summary:** A low‑privileged Kubernetes user can inject Jinja2 template code via malicious custom resource values processed by Ansible Operator Plugins, leading to arbitrary code execution and cluster‑wide privilege escalation.

**Affected Features / Interoperability:** Ansible Operator Plugins, custom resource handling, Jinja2 templating, operator’s service account, and cluster‑wide resources.

**Source:** 
- https://access.redhat.com/errata/RHSA-2026:68695  
- https://access.redhat.com/errata/RHSA-2026:87120  
- https://access.redhat.com/errata/RHSA-2026:87124

**Actions:**
- **Fix:** Apply Red Hat errata RHSA‑2026:68695, 87120, 87124 (upgrade to patched Ansible Operator versions).
- **Workaround:** Restrict custom resource creation, disable Jinja2 evaluation, and enforce admission controllers.
- **Tradeoff:** Limiting custom resources may reduce automation flexibility.

#### Kubernetes — CVE-2026-127077 (CVSS 7.1 HIGH)

**Summary:** Authenticated users can tamper with BuildPiper’s environment creation API (POST /api/v1/project/{project_id}/env/) to target another project’s cluster, bypassing project isolation and deploying code into unauthorized clusters.

**Affected Features / Interoperability:** BuildPiper environment creation API, project isolation, cluster assignment logic, CI/CD pipelines.

**Source:** 
- https://gist.github.com/neelkotnis/e6ba937a2ea3f06fc0a79bd6193e4574  
- https://www.buildpiper.io/  
- https://www.vulncheck.com/advisories/opstree-buildpiper-before-2.7.0-authorization-bypass-via-environment-creation-api

**Actions:**
- **Fix:** Upgrade BuildPiper to 2.7.0+.
- **Workaround:** Enforce strict RBAC, validate cluster_id against assigned clusters, and audit API calls.
- **Tradeoff:** Stricter validation may impact multi‑tenant workflows.

#### Kubernetes — CVE- 2026-121374 (CVSS UNSCORED)

**Summary:** A user with permission to edit rules in a folder can inject arguments via the “Exclude nodes based on their role” option in Checkmk’s Kubernetes special agent, writing arbitrary files and achieving code execution as the site user.

**Affected Features / Interoperability:** Checkmk Kubernetes special agent, rule editing, node role exclusion feature, file system access.

**Source:** https://checkmk.com/werk/17994

**Actions:**
- **Fix:** Upgrade Checkmk to ≥2.5.0p19 (or appropriate patched version).
- **Workaround:** Restrict rule‑editing permissions and apply principle of least privilege.
- **Tradeoff:** Limiting rule editing may reduce operational flexibility.

#### Docker — CVE-2026-129433 (CVSS 9.9 CRITICAL)

**Summary:** Authenticated organization members can inject shell commands via the serviceName parameter in Dokploy’s backup.create/update tRPC procedures, leading to root command execution and host takeover through the mounted Docker socket.

**Affected Features / Interoperability:** Dokploy backup tRPC procedures, serviceName parameter, getComposeContainerCommand, Docker socket mounting, host OS.

**Source:** 
- https://github.com/Dokploy/dokploy  
- https://github.com/Dokploy/dokploy/blob/v0.31.0/packages/server/src/utils/backups/utils.ts#L152  
- https://github.com/Dokploy/dokploy/commit/b24006e16e95a10ce3daf739d06ac783e5c70ba0

**Actions:**
- **Fix:** Upgrade Dokploy to version 0.31.1 or later.
- **Workaround:** Sanitize serviceName input, restrict backup operations, and remove Docker socket mount.
- **Tradeoff:** Input sanitization may break existing backup workflows; removing the Docker socket can affect container management.

#### Docker — CVE-2026-67543 (CVSS 8.8 HIGH)

**Summary:** Heym’s skill executor runs user Python code without Docker isolation, exposing the backend to arbitrary code execution despite the tool executor using a sandbox.

**Affected Features / Interoperability:** heym skill_python_executor.py, Python tool executor, backend execution context, process isolation.

**Source:** 
- https://github.com/heymrun/heym/commit/2155057f4153a1e3a7b789d104f7fa96e92964e5  
- https://github.com/heymrun/heym/commit/28bb2901e4dea128ac493f67ee9478d230b7a3d7  
- https://github.com/heymrun/heym/releases/tag/0.0.70

**Actions:**
- **Fix:** Upgrade heym to version 0.0.70 or later.
- **Workaround:** Enforce Docker sandbox for all Python skill execution and restrict backend privileges.
- **Tradeoff:** Using Docker adds overhead and complexity.

#### Docker — CVE-2026-126384 (CVSS 7.5 HIGH)

**Summary:** n8n bundles a vulnerable GraphicsMagick library used by the Edit Image node; attackers who can supply malicious images (e.g., via webhook) can achieve remote code execution on the n8n instance.

**Affected Features / Interoperability:** n8n Edit Image node, GraphicsMagick library, image processing pipeline, webhook input.

**Source:** 
- https://github.com/n8n-io/n8n/security/advisories/GHSA-f2cw-9483-7vcp  
- https://www.vulncheck.com/advisories/n8n-before-1.123.89-rce-via-bundled-graphicsmagick-in-edit-image-node

**Actions:**
- **Fix:** Upgrade n8n to the latest patched version (1.123.89, 2.45.5, 2.46.1, 3.0.1).
- **Workaround:** Disable the Edit Image node, use external image processing, and restrict webhook sources.
- **Tradeoff:** Disabling the node may reduce workflow automation capabilities.

#### Docker — CVE-2026-124969 (CVSS 7.1 HIGH)

**Summary:** The Optimole WordPress plugin lacks proper path validation in replace_urls_in_value, allowing unauthenticated attackers to delete arbitrary files (e.g., wp‑config.php) and potentially achieve remote code execution.

**Affected Features / Interoperability:** Optimole plugin for WordPress, replace_urls_in_value function, file system operations, WordPress core files.

**Source:** 
- https://plugins.trac.wordpress.org/browser/optimole-wp/tags/4.2.19/inc/media_rename/attachment_db_renamer.php#L319  
- https://plugins.trac.wordpress.org/browser/optimole-wp/tags/4.2.19/inc/media_rename/attachment_db_renamer.php#L415  
- https://plugins.trac.wordpress.org/browser/optimole-wp/tags/4.2.19/inc/media_rename/attachment_db_renamer.php#L548

**Actions:**
- **Fix:** Upgrade Optimole plugin to a version > 4.2.19.
- **Workaround:** Disable the plugin, enforce file permission restrictions, and use security plugins to block malicious requests.
- **Tradeoff:** Disabling the plugin may affect image optimization workflows.
