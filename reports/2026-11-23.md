# Security Digest — 2026-11-23

## Cloud Security

The most urgent threat is the Kubernetes CRI‑O checkpoint restore vulnerability (CVE‑2026‑92574), a high‑severity (CVSS 8.8) issue that enables a malicious checkpoint to bypass the destination security context and execute with elevated privileges, presenting an immediate risk to Kubernetes cluster security.  

### Formal Vulnerabilities

#### Google Cloud Platform — CVE-2026-126054 (CVSS UNSCORED UNSCORED)  
**Summary:** A path traversal flaw in Google Cloud Dataform, BigQuery Studio, and Colab Enterprise allows an authenticated remote attacker to read private files and create arbitrary files across tenant repositories via crafted workspace operations and Git integration requests.  

**Affected Features / Interoperability:** Impacts workspace directory handling and Git integration features in Dataform, BigQuery Studio, and Colab Enterprise; can break tenant isolation and expose confidential data.  

**Source:** https://docs.cloud.google.com/bigquery/docs/release-notes#November_19_2026; https://docs.cloud.google.com/dataform/docs/release-notes#November_19_2026; https://docs.cloud.google.com/support/bulletins/#gcp-2026-084  

**Actions:**  
- Fix: Patched on 10 October 2026; no customer action required.  
- Workaround: Not needed; if required, restrict workspace operations or disable Git integration.  
- Tradeoff: No significant tradeoff.  

#### Kubernetes — CVE-2026-92574 (CVSS 8.8 HIGH)  
**Summary:** A flaw in CRI‑O checkpoint restore lets a user create a pod from a malicious checkpoint, causing the restored container process to retain original credentials, Linux capabilities, no_new_privs, and seccomp state, thereby bypassing the destination security context and executing with elevated privileges.  

**Affected Features / Interoperability:** Affects CRI‑O container runtime and Kubernetes security context enforcement; can break container isolation and enable privilege escalation across pod boundaries.  

**Source:** https://access.redhat.com/security/cve/CVE-2026-92574; https://bugzilla.redhat.com/show_bug.cgi?id=2535436  

**Actions:**  
- Fix: Apply supported CRI‑O version upgrades (1.34+); Red Hat OCP 4.17+ includes the fix.  
- Workaround: Restrict use of checkpoint restore or enforce stricter security context policies; not fully mitigable.  
- Tradeoff: May limit checkpoint functionality and require manual security context configuration.  

#### Docker — CVE-2026-134452 (CVSS 8.8 HIGH)  
**Summary:** Dockhand versions before 1.0.57 merge stack secret environment variables (e.g., PATH) into the Docker Compose spawn environment without filtering reserved keys, allowing an authenticated attacker with stacks:edit permission to set PATH to a malicious directory and trigger arbitrary command execution as the Dockhand server process user.  

**Affected Features / Interoperability:** Impacts Dockhand stack deployment functionality; can lead to remote code execution on the server, compromising host security.  

**Source:** https://github.com/Finsys/dockhand/security/advisories/GHSA-8fh8-h5v2-wmj4; https://www.vulncheck.com/advisories/dockhand-before-1.0.57-rce-via-path-poisoning-in-stack-deploy; https://github.com/Finsys/dockhand/security/advisories/GHSA-8fh8-h5v2-wmj4  

**Actions:**  
- Fix: Upgrade to Dockhand 1.0.57 or later.  
- Workaround: Avoid using stack deploy with untrusted stacks or sanitize the PATH variable before deployment.  
- Tradeoff: May reduce stack deployment flexibility and require additional validation steps.  

#### KindleEar — CVE-2026-135436 (CVSS 8.8 HIGH)  
**Summary:** KindleEar 3.0.0‑3.5.3 permits authenticated non‑admin users to upload malicious recipes that trigger un‑sandboxed exec() in calibre compile_recipe, achieving root code execution in the Docker container and exposing password hashes.  

**Affected Features / Interoperability:** Affects the recipe upload feature and Docker container execution environment; can compromise the host and steal credentials.  

**Source:** https://github.com/cdhigh/KindleEar/blob/62cb25fdd2e9760ea26317b324f35f6ed2b49c53/application/view/subscribe.py#L344-L347; https://github.com/cdhigh/KindleEar/commit/3ef6fbed527453b1b64c610e1fb880144fa7ec00; https://github.com/cdhigh/KindleEar/issues/753  

**Actions:**  
- Fix: Upgrade to KindleEar 3.5.4 or later (patch not listed but implied).  
- Workaround: Disable recipe upload for non‑admin users or sandbox the compile_recipe process.  
- Tradeoff: May limit recipe sharing capabilities and add operational overhead.  

#### Hermes Agent — CVE-2026-130164 (CVSS 7.8 HIGH)  
**Summary:** Hermes Agent versions 0.21.6‑0.23.1 read a backend‑writable screen environment file without validating keys or values and merge its entries into the environment of processes started on the agent machine when using docker or ssh terminal backends, potentially allowing arbitrary code execution or privilege escalation.  

**Affected Features / Interoperability:** Impacts environment variable handling for agents using docker or ssh terminal backends; can break isolation and enable code execution.  

**Source:** https://github.com/NousResearch/hermes-agent/commit/9c44c34ac74bec800ca25c32e7d5e9b1dd47168d; https://github.com/NousResearch/hermes-agent/pull/154487; https://github.com/NousResearch/hermes-agent/security/advisories/GHSA-p22p-9ph6-gmrh  

**Actions:**  
- Fix: Update to version 0.23.2 or later (patch not explicitly listed).  
- Workaround: Ensure the backend‑writable screen environment file is not writable by untrusted users or disable the vulnerable backend configuration.  
- Tradeoff: May restrict use of certain terminal backends or require stricter file permissions.  

#### kube-compare — CVE-2026-87114 (CVSS 7.1 HIGH)  
**Summary:** kube-compare incorrectly executes an untrusted container image’s entrypoint when processing a container:// reference path, allowing a remote attacker to achieve arbitrary code execution on the operator’s workstation, potentially with root‑mediated Docker daemon privileges.  

**Affected Features / Interoperability:** Affects the kube-compare utility; can compromise the workstation and elevate privileges via the Docker daemon.  

**Source:** https://access.redhat.com/errata/RHSA-2026:74381; https://access.redhat.com/errata/RHSA-2026:74384; https://access.redhat.com/errata/RHSA-2026:74430  

**Actions:**  
- Fix: Apply patched version of kube-compare that correctly handles container:// references.  
- Workaround: Avoid using container:// references or run kube-compare with limited privileges.  
- Tradeoff: May limit functionality of the tool.  

#### MyMangaDB — CVE-2026-77295 (CVSS UNSCORED UNSCORED)  
**Summary:** Unauthenticated access to /api/v1/database/export in MyMangaDB < 2.7.2 returns a ZIP containing the live SQLite database and cover‑image library, exposing the users table and hashed passwords for offline attacks.  

**Affected Features / Interoperability:** Impacts the unauthenticated database export endpoint; can lead to data breach and credential theft.  

**Source:** https://github.com/FabianRolfMatthiasNoll/MyMangaDB/commit/2ad34ea785c01d096b38a01420d56fc5a1078db4; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/releases/tag/v2.7.2; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/security/advisories/GHSA-66wj-vwff-vp3p  

**Actions:**  
- Fix: Upgrade to version 2.7.2 or later.  
- Workaround: Disable the unauthenticated export endpoint or restrict access to it.  
- Tradeoff: May reduce convenience of export functionality.  

#### MyMangaDB — CVE-2026-77296 (CVSS UNSCORED UNSCORED)  
**Summary:** Unauthenticated /api/v1/images/manga/save handler in MyMangaDB < 2.7.2 joins a client‑controlled filename to IMAGE_SAVE_PATH without confinement, allowing traversal to overwrite process‑writable files such as the live SQLite database, while the image content type is not validated.  

**Affected Features / Interoperability:** Affects the image save endpoint; can enable file overwrite and database tampering.  

**Source:** https://github.com/FabianRolfMatthiasNoll/MyMangaDB/commit/2ad34ea785c01d096b38a01420d56fc5a1078db4; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/releases/tag/v2.7.2; https://github.com/FabianRolfMatthiasNoll/MyMangaDB/security/advisories/GHSA-66h5-6vhv-5w76  

**Actions:**  
- Fix: Upgrade to version 2.7.2 or later.  
- Workaround: Sanitize filenames, enforce strict write permissions, or disable the endpoint.  
- Tradeoff: May limit functionality of image handling.
