# Security Digest — 2026-10-12

## Database

The most urgent issue is **CVE‑2025‑34227**, a high‑severity (CVSS 8.8) authenticated command injection in Nagios XI wizards that affect MySQL and MongoDB monitoring. Attackers with valid Nagios credentials can inject shell commands into wizard arguments, leading to arbitrary code execution as the `nagios` user on the underlying host. This vulnerability is actively exploitable and should be patched immediately.

### Formal Vulnerabilities

#### MySQL — CVE-2025-34227 (CVSS 8.8 HIGH)

**Summary:** An authenticated command injection exists in Nagios XI versions prior to 2026R1 within the MySQL Query wizard (and other DB wizards). Attackers with valid Nagios credentials can inject shell characters into wizard arguments, leading to arbitrary code execution on the host as the `nagios` user.

**Affected Features / Interoperability:** The MySQL Query wizard, MySQL Server wizard, and associated Nagios XI monitoring components are impacted. This can affect downstream database monitoring, alerting, and potentially compromise the underlying database servers that are monitored.

**Source:** 
- https://theyhack.me/CVE-2025-34227-Nagios-XI-Wizard-Command-Injection/
- https://www.nagios.com/changelog/
- https://www.nagios.com/products/security/
- https://www.vulncheck.com/advisories/nagios-xi-config-wizard-auth-command-injection

**Actions:**
- **Fix:** Upgrade Nagios XI to version 2026R1 or later.
- **Workaround:** Restrict access to the Nagios XI web UI to trusted networks and enforce multi‑factor authentication; consider disabling the vulnerable wizards if not needed.
- **Tradeoff:** Limiting access may reduce operational convenience; disabling wizards reduces monitoring granularity.

**Affected Features / Interoperability:** The login handler and underlying MySQL database queries are affected. This can break authentication and allow unauthorized access to recruitment data.

## Cloud Security

The most urgent item is **CVE-2025-59823 (CVSS 9.9)** in Project Gardener's Terraform/Terraformer integration: a code-injection flaw in multiple cloud-provider extensions (AWS, Azure, GCP, OpenStack) that lets a project admin escalate to full control of the seed cluster managing their shoot clusters. No CISA KEV entries appear in this dataset, so this highest-CVSS vulnerability — affecting the control plane of managed Kubernetes clusters — takes top priority. Also critical: Azure API Management cross-tenant signup bypass (CVE-2025-66390, CVSS 9.8), Docker/Termix authentication bypass (CVE-2025-59951, CVSS 9.1), and three Argo CD DoS flaws (CVE-2025-59531/59537/59538, CVSS 7.5 each).

### Formal Vulnerabilities

#### Microsoft Azure — CVE-2025-66390 (CVSS 9.8 CRITICAL)
**Summary:** When self-service signup (Basic Auth) is enabled in one Azure API Management tenant, an attacker can manipulate the Host header or tenant identifier to register against a different tenant that has signup disabled in the UI. The underlying API endpoint still accepts cross-tenant requests, effectively bypassing the UI-level disable control. Microsoft disputes this as a security boundary crossing, calling it a configuration/state issue.

**Affected Features / Interoperability:** Azure API Management self-service signup endpoint; tenant isolation controls. Downstream impact: unauthorized developer accounts created in tenants that intended to block signup, potentially leading to API consumption abuse or further social-engineering footholds.

**Source:** https://github.com/bountyyfi/Azure-APIM-Cross-Tenant-Signup-Bypass, https://github.com/bountyyfi/Azure-APIM-Cross-Tenant-Signup-Bypass/security/advisories/GHSA-vcwf-73jp-r7mv

**Actions:**
- Fix: No official patch version cited; Microsoft considers this a configuration issue. Mitigate by ensuring signup is disabled at the API level (e.g., via policy or network restriction) rather than only in the UI.
- Workaround: Block or monitor cross-tenant Host-header variations at the gateway/WAF layer; disable Basic Auth signup entirely if not required.
- Tradeoff: Disabling Basic Auth signup removes legitimate self-service onboarding; WAF rules may require tuning to avoid false positives.

**Summary:** Code injection in Gardener Extensions for AWS (pre-1.64.0), Azure (pre-1.55.0), OpenStack (pre-1.49.0), and GCP (pre-1.46.0) providers. A user with admin privileges in a Gardener project can exploit Terraformer-driven infrastructure provisioning to execute code on the seed cluster, gaining full control over the management plane of all shoot clusters.

**Affected Features / Interoperability:** Gardener Extension providers (AWS, Azure, GCP, OpenStack) when Terraformer is used/enabled for infrastructure provisioning. Downstream: complete seed-cluster compromise, affecting all managed shoot clusters, their workloads, and any integrated secrets/identity systems.

**Source:** https://github.com/gardener/gardener-extension-provider-aws/releases/tag/v1.64.0, https://github.com/gardener/gardener-extension-provider-aws/security/advisories/GHSA-227x-7mh8-3cf6, https://github.com/gardener/gardener-extension-provider-azure/releases/tag/v1.55.0, https://github.com/gardener/gardener-extension-provider-gcp/releases/tag/v1.46.0, https://github.com/gardener/gardener-extension-provider-openstack/releases/tag/v1.49.0

**Actions:**
- Fix: Upgrade Terragrunt to ≥1.0.4.
- Workaround: Pin modules to trusted sources/registries; run Terragrunt in isolated ephemeral environment (clean container per run).
- Tradeoff: Ephemeral environments increase CI/CD runtime and storage; trusted-source pinning reduces module flexibility.
