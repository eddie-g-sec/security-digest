# Security Digest — 2026-11-03

## Cloud Security

The most urgent finding is **CVE-2026-120306** and **CVE-2026-120307** (both CVSS 9.9 CRITICAL) in the Beta9 Kubernetes build worker, which allow container escape to root on the host via chroot isolation bypass and path traversal in the sandbox file API — effectively granting full control of the build worker node. No CISA KEV-confirmed exploits appear in this dataset, so the highest theoretical severity drives priority. AWS Multi Model Server (EOL) has a critical path traversal (CVE-2026-115812, CVSS 9.8) with no patch available; migration is the only fix. Azure kaniko (CVE-2026-105769, CVSS 9.3) leaks Entra ID tokens to attacker-controlled registries. Google Cloud Run MCP has an unscored bucket-squatting flaw (CVE-2026-85297) requiring upgrade to 1.11.0. Kubernetes also sees Airflow JWT exposure (CVE-2026-49298, CVSS 8.8), Kubewarden case-sensitivity bypass (CVE-2026-63121, CVSS 6.3), Temporal command injection (CVE-2026-120091, unscored), and OSAC operator kubeconfig exec injection (CVE-2026-62284, unscored). Docker surfaces ShowDoc code injection (CVE-2026-120203, CVSS 8.8), Jpom cross-workspace Docker host takeover (CVE-2026-120460, CVSS 8.8), ESPHome unauthenticated dashboard access (CVE-2026-59177, CVSS 8.8), and boneIO excessive privileges (CVE-2026-77055, unscored). Terraform's Atlantis has a workspace-name shell injection (CVE-2026-116676, CVSS 8.8).

### Formal Vulnerabilities

#### AWS — CVE-2026-115812 (CVSS 9.8 CRITICAL)
**Summary:** Relative path traversal during model archive extraction in AWS Multi Model Server 1.1.11 and earlier allows remote actors to execute arbitrary code via a crafted model archive. The server is end-of-life; no fixed version exists.
**Affected Features / Interoperability:** Multi Model Server model archive extraction; impacts any downstream model serving workloads using this component. Migration to a supported model serving solution is required.
**Source:** https://aws.amazon.com/security/security-bulletins/2026-148-aws/
**Actions:**
- Fix: No patch available; Multi Model Server is EOL.
- Workaround: Discontinue use and migrate to a supported model serving solution (e.g., SageMaker, TorchServe, Triton).
- Tradeoff: Migration effort; potential model compatibility changes.

#### AWS — CVE-2026-115418 (CVSS 7.3 HIGH)
**Summary:** SQL injection in the database-query custom resource handlers in AWS CDK @aws-cdk/aws-redshift-alpha module before 2.274.0-alpha.0 allows a third party who can influence construct property values to run SQL statements with Amazon Redshift superuser privileges, including granting access to all cluster users. Exploitable via crafted user names, comments, or passwords.
**Affected Features / Interoperability:** CDK Redshift Alpha construct property handling; impacts Redshift cluster user/permission management and any automation using these constructs.
**Source:** https://aws.amazon.com/security/security-bulletins/2026-151-aws/, https://github.com/aws/aws-cdk/releases#release-v2.274.0, https://github.com/aws/aws-cdk/security/advisories/GHSA-25hh-xvj4-2cqv
**Actions:**
- Fix: Upgrade to @aws-cdk/aws-redshift-alpha version 2.274.0-alpha.0 or later.
- Workaround: Review and restrict construct property inputs; audit existing table grants to PUBLIC.
- Tradeoff: Alpha module upgrades may introduce breaking changes; test thoroughly.

#### AWS — CVE-2026-115813 (CVSS 5.8 MEDIUM)
**Summary:** Server-side request forgery in the model download path in AWS Multi Model Server 1.1.11 and earlier allows remote actors to send requests to internal network destinations via a crafted model URL. The server is end-of-life; no fixed version exists.
**Affected Features / Interoperability:** Model download functionality; could expose internal metadata services or other network endpoints.
**Source:** https://aws.amazon.com/security/security-bulletins/2026-148-aws/
**Actions:**
- Fix: No patch available; Multi Model Server is EOL.
- Workaround: Discontinue use and migrate to a supported model serving solution.
- Tradeoff: Migration effort; potential model compatibility changes.

#### Microsoft Azure — CVE-2026-105769 (CVSS 9.3 CRITICAL)
**Summary:** kaniko before 1.25.20 sends a Microsoft Entra ID (Azure AD) access token for Azure Resource Manager to an attacker-controlled registry host. The Azure Container Registry credential helper uses an unanchored regex, accepting any hostname containing `.azurecr.io`, `.azurecr.cn`, `.azurecr.de`, or `.azurecr.us`. kaniko consults this helper for any registry without credentials in Docker config (excluding Google/Amazon ECR) before contacting the registry.
**Affected Features / Interoperability:** kaniko container image builds that pull/push to registries; impacts CI/CD pipelines using kaniko with Azure credentials. Token leakage could allow Azure Resource Manager API access.
**Source:** https://github.com/chainguard-forks/kaniko/pull/495, https://github.com/chainguard-forks/kaniko/releases/tag/v1.25.20, https://github.com/chainguard-forks/kaniko/security/advisories/GHSA-5q7h-w9jf-cx97
**Actions:**
- Fix: Upgrade kaniko to v1.25.20 or later.
- Workaround: Ensure Docker config contains explicit credentials for all registries used; avoid unauthenticated registry pulls in kaniko.
- Tradeoff: Credential management overhead; may require pipeline changes.

#### Google Cloud Platform — CVE-2026-85297 (CVSS UNSCORED)
**Summary:** Bucket squatting in Google Cloud Run MCP versions prior to 1.11.0 allows an attacker to intercept and access proprietary source code, execute arbitrary code, and exfiltrate data.
**Affected Features / Interoperability:** Cloud Run MCP (Model Control Plane) bucket interactions; impacts source code confidentiality and integrity for deployments using affected versions.
**Source:** https://github.com/GoogleCloudPlatform/cloud-run-mcp/releases/tag/v1.11.0
**Actions:**
- Fix: Upgrade to Cloud Run MCP version 1.11.0 or later.
- Workaround: None specified; restrict network access to MCP buckets if possible.
- Tradeoff: No significant tradeoff for upgrade.

#### Kubernetes — CVE-2026-120306 (CVSS 9.9 CRITICAL)
**Summary:** Beta9 turns each shell command in a tenant image definition into a Dockerfile RUN line and executes it with Buildah on the build worker. The worker uses `BUILDAH_ISOLATION=chroot` without `--isolation`, so steps only change filesystem root while keeping the worker pod's PID, network, IPC, and user namespaces, running as uid 0 with `CAP_DAC_OVERRIDE`. The worker's filesystem (accessible via `/proc/1/root`) contains runc, buildah, and runsc binaries, enabling container escape to host root.
**Affected Features / Interoperability:** Beta9 build worker tenant image builds; impacts any multi-tenant Kubernetes build platform using Beta9. Downstream: tenant workloads, build isolation, host compromise.
**Source:** https://github.com/beam-cloud/beta9, https://github.com/beam-cloud/beta9/commit/a28bf12cf0007c792a25d8ed282b4e8bf6f30393, https://github.com/beam-cloud/beta9/pull/1897
**Actions:**
- Fix: Apply patch from commit a28bf12cf0007c792a25d8ed282b4e8bf6f30393 (included in PR #1897); upgrade Beta9 to a version containing the fix.
- Workaround: Disable tenant image builds or run workers with stricter isolation (e.g., `--isolation=oci` if supported), drop `CAP_DAC_OVERRIDE`, use user namespaces.
- Tradeoff: Stricter isolation may break build compatibility; performance overhead.

#### Kubernetes — CVE-2026-120307 (CVSS 9.9 CRITICAL)
**Summary:** Beta9 worker serves the sandbox file API from outside the container. `getHostPathFromContainerPath` joins tenant container paths onto mount sources; a long run of parent-directory segments after a mount prefix check can name any absolute path on the worker. Paths matching no mount are joined onto the container root and opened in the worker's filesystem, allowing absolute symlink traversal to read/write arbitrary host files.
**Affected Features / Interoperability:** Beta9 sandbox file API; impacts file upload/download functionality in multi-tenant builds. Downstream: host filesystem exposure, potential code execution via binary replacement.
**Source:** https://github.com/beam-cloud/beta9, https://github.com/beam-cloud/beta9/commit/a28bf12cf0007c792a25d8ed282b4e8bf6f30393, https://github.com/beam-cloud/beta9/pull/1897
**Actions:**
- Fix: Apply patch from commit a28bf12cf0007c792a25d8ed282b4e8bf6f30393 (included in PR #1897); upgrade Beta9.
- Workaround: Disable sandbox file API; restrict mount destinations; validate and sanitize tenant-supplied paths.
- Tradeoff: Loss of file transfer feature; may break tenant workflows.

#### Kubernetes — CVE-2026-49298 (CVSS 8.8 HIGH)
**Summary:** Apache Airflow's KubernetesExecutor passes JWT tokens (used by worker pods to authenticate against the Execution API) as command-line arguments visible in the pod spec. An authenticated UI/API user with Kubernetes read-only access (e.g., `pods/get` in the Airflow namespace) can harvest the JWT from `kubectl describe pod` and call state-mutating Execution API endpoints — triggering DAG runs, clearing runs, reading/writing Variables/Connections/XComs — as if they were a running task. Affects deployments using KubernetesExecutor.
**Affected Features / Interoperability:** Airflow KubernetesExecutor worker pod spec; impacts Execution API authentication, DAG run control, Variable/Connection/XCom integrity.
**Source:** https://github.com/apache/airflow/pull/60108, https://lists.apache.org/thread/wo09vrks8189dzsot39rvrx3vnx102tt
**Actions:**
- Fix: Upgrade Airflow to a version with the fix (PR #60108).
- Workaround: Restrict `pods/get` RBAC permissions for non-admin users; rotate JWT secrets frequently; monitor Execution API audit logs.
- Tradeoff: Reduced visibility for developers; operational overhead.

#### Kubernetes — CVE-2026-20770 (CVSS 6.7 MEDIUM)
**Summary:** Protection mechanism failure in Cluster Management Toolkit for Kubernetes before v0.8.5 (Ring 3: User Applications) may allow privilege escalation. A system software adversary with a privileged user and low-complexity attack may escalate privileges via local access with passive user interaction. Impacts confidentiality, integrity, and availability (high).
**Affected Features / Interoperability:** Cluster Management Toolkit user application components; impacts local privilege boundaries on managed nodes.
**Source:** https://intel.com/content/www/us/en/security-center/advisory/intel-sa-01460.html
**Actions:**
- Fix: Upgrade to Cluster Management Toolkit v0.8.5 or later.
- Workaround: Restrict local privileged access; enforce least-privilege for user applications.
- Tradeoff: May limit legitimate administrative workflows.

#### Kubernetes — CVE-2026-63121 (CVSS 6.3 MEDIUM)
**Summary:** Kubewarden `trusted-repos-policy` before 2.1.2 compares image `registry` hostnames against reject/allow lists case-sensitively, though DNS names are case-insensitive. An image with uppercase/mixed-case registry hostname can bypass a rejection rule for the equivalent lowercase host, causing the admission policy to accept a prohibited image.
**Affected Features / Interoperability:** Kubewarden trusted-repos-policy admission control; impacts container image registry enforcement in Kubernetes clusters.
**Source:** https://github.com/kubewarden/policies/commit/bc5597fcbbb0bc464b714ca7ff645c9743dea41b, https://github.com/kubewarden/policies/security/advisories/GHSA-8p62-9vh2-272p, https://github.com/kubewarden/policies/tree/trusted-repos-policy/v2.1.2
**Actions:**
- Fix: Upgrade trusted-repos-policy to v2.1.2 or later.
- Workaround: Ensure reject/allow lists include all case variants; use mutating policies to normalize registry hostnames to lowercase.
- Tradeoff: Policy maintenance overhead; potential false positives.

#### Kubernetes — CVE-2026-120091 (CVSS UNSCORED)
**Summary:** Temporal Server's Worker Controller Instance module (`go.temporal.io/auto-scaled-workers`) registers a `k8s` compute provider that builds its Kubernetes client from the caller's request configuration rather than operator configuration. Building and using that client can run a command of the caller's choosing on the Worker Service host under the server's account. Two frontend operations reach the provider: CreateWorker and UpdateWorker.
**Affected Features / Interoperability:** Temporal auto-scaled workers Kubernetes provider; impacts worker lifecycle management APIs. Downstream: arbitrary command execution on Temporal worker service host.
**Source:** https://github.com/temporalio/temporal-auto-scaled-workers/pull/165, https://github.com/temporalio/temporal/pull/12843, https://github.com/temporalio/temporal/releases/tag/v1.31.5
**Actions:**
- Fix: Upgrade Temporal to v1.31.5 or later (includes fix from PR #12843).
- Workaround: Restrict access to CreateWorker/UpdateWorker APIs; validate and sanitize client configuration inputs.
- Tradeoff: Limits dynamic worker scaling capabilities.

#### Kubernetes — CVE-2026-62284 (CVSS UNSCORED)
**Summary:** OSAC operator's `console-proxy` `RemoteConfigResolver` parses Kubernetes Secret kubeconfig data with `clientcmd.RESTConfigFromKubeConfig` without sanitizing the resulting `rest.Config`. An attacker who can create/modify a Secret labeled `osac.openshift.io/remote-cluster-kubeconfig: "true"` in a namespace with proxy RoleBinding read access can supply `users[].user.exec`. When `rest.TransportFor` builds the HTTP transport for an upstream WebSocket connection, client-go invokes that exec credential plugin, achieving code execution on the proxy host.
**Affected Features / Interoperability:** OSAC operator console-proxy remote cluster configuration; impacts multi-cluster management via Secrets.
**Source:** https://github.com/osac-project/osac-operator/commit/7e4222b6ab465fc00606c8cfed980b226820cb1b, https://github.com/osac-project/osac-operator/commit/86466378aa3603253dca7fa2f59a2733af0dc092, https://github.com/osac-project/osac-operator/pull/321
**Actions:**
- Fix: Apply patches from commits 7e4222b6 and 86466378 (included in PR #321); upgrade OSAC operator.
- Workaround: Restrict Secret create/update permissions for the labeled key; validate kubeconfig content before applying.
- Tradeoff: Limits dynamic remote cluster onboarding.

#### Docker — CVE-2026-120203 (CVSS 8.8 HIGH)
**Summary:** ShowDoc 2.8.14 before 3.9.6 contains a code injection vulnerability in its Mock feature allowing authenticated users to execute shell commands through mockjs templates. Attackers store a template via `MockController::add` with escaped parentheses that mockjs evaluates with `eval()`, then trigger it through `MockController::infoByKey` to run commands as root in the official Docker image.
**Affected Features / Interoperability:** ShowDoc Mock feature (template management); impacts Docker deployments running ShowDoc as root. Downstream: container escape, host command execution.
**Source:** https://gist.github.com/LioTree/028af150fd991cf9924dd2c7d5912e54, https://github.com/star7th/showdoc, https://github.com/star7th/showdoc/blob/v3.9.5/mock/index.js#L42
**Actions:**
- Fix: Upgrade ShowDoc to 3.9.6 or later.
- Workaround: Run ShowDoc as non-root user; disable Mock feature if not needed; restrict authenticated user permissions.
- Tradeoff: Non-root may break file permissions; Mock feature loss.

#### Docker — CVE-2026-120460 (CVSS 8.8 HIGH)
**Summary:** Jpom through 2.11.12 contains a cross-workspace authorization bypass allowing authenticated users to manage other workspaces' Docker hosts by supplying foreign Docker asset IDs. Attackers with Docker permission in any workspace can control containers, images, volumes, and networks, including creating privileged containers with host bind mounts.
**Affected Features / Interoperability:** Jpom Docker host management across workspaces; impacts multi-tenant Docker orchestration. Downstream: privileged container creation, host filesystem access.
**Source:** https://github.com/dromara/Jpom/blob/v2.11.12/modules/server/src/main/java/org/dromara/jpom/controller/docker/DockerContainerController.java#L48-L51, https://github.com/dromara/Jpom/blob/v2.11.12/modules/server/src/main/java/org/dromara/jpom/controller/docker/DockerImagesController.java#L48-L51, https://github.com/dromara/Jpom/commit/ff09fe8095a792cea9c4b8babd93a333655d0a28
**Actions:**
- Fix: Upgrade Jpom beyond 2.11.12 (patch in commit ff09fe8).
- Workaround: Enforce workspace isolation via separate Jpom instances; restrict Docker asset ID visibility.
- Tradeoff: Operational complexity; loss of centralized management.

#### Docker — CVE-2026-59177 (CVSS 8.8 HIGH)
**Summary:** ESPHome Device Builder Dashboard prior to 1.0.10 binds the Home Assistant add-on's trusted `ingress` site to `0.0.0.0` while skipping dashboard authentication (expecting supervisor to authenticate upstream). Host networking (required for mDNS) also binds this no-auth site to the Home Assistant host's LAN interface. Any device on the local network can connect directly to the ingress port, bypass the supervisor, and obtain full dashboard access without credentials.
**Affected Features / Interoperability:** ESPHome Device Builder Dashboard Home Assistant add-on ingress; impacts local network exposure of unauthenticated dashboard.
**Source:** https://github.com/esphome/device-builder/commit/b6387db3f8bf1d3df5771f40e9856b959ae4f6a1, https://github.com/esphome/device-builder/pull/1565, https://github.com/esphome/device-builder/releases/tag/1.0.10
**Actions:**
- Fix: Upgrade to ESPHome Device Builder Dashboard 1.0.10 or later.
- Workaround: Disable host networking for the add-on; restrict LAN access via firewall; enable dashboard authentication.
- Tradeoff: Host networking loss may break mDNS device discovery.

#### Docker — CVE-2026-77055 (CVSS UNSCORED)
**Summary:** boneIO black_debian_images gives the boneio service account excessive privileges, including full passwordless sudo access and membership in the docker group. A local attacker compromising the boneio user can escalate to root. Fixed in version 1.6.0: image removes sudoers rule and docker group membership when sealed; devices in field have both removed by migrations shipped with boneio 1.6.0 applied on first start after upgrade. Privileged operations now go through helpers accepting only a fixed command set.
**Affected Features / Interoperability:** boneIO Debian-based device images; impacts local privilege escalation on IoT/edge devices running boneIO.
**Source:** https://boneio.eu/en/docs/black, https://cert.pl/en/posts/2026/10/CVE-2026-77052
**Actions:**
- Fix: Upgrade boneIO to 1.6.0 or later; apply migrations on existing devices.
- Workaround: Remove boneio user from docker group; restrict sudoers; run boneio in a container with dropped capabilities.
- Tradeoff: May break boneIO's device management operations; containerization adds complexity.

#### Terraform — CVE-2026-116676 (CVSS 8.8 HIGH)
**Summary:** Atlantis 0.4.0 through 0.47.1 passes the pull-request-controlled workspace value from `atlantis.yaml` into Terraform command arguments joined with `strings.Join(args, " ")` and executed through `sh -c`. An authenticated contributor whose PR is eligible for an Atlantis plan can include shell metacharacters in the workspace name, causing arbitrary command execution as the Atlantis service account without custom workflows, apply permission, or malicious Terraform code.
**Affected Features / Interoperability:** Atlantis Terraform plan/apply automation via webhook; impacts workspace name handling in PR-triggered runs. Downstream: CI/CD service account compromise.
**Source:** https://github.com/runatlantis/atlantis/commit/8dd22b4d0a9d7c129fdbf6a3398dd1c4cf8c3a59, https://github.com/runatlantis/atlantis/commit/f04df0d53f0544d9eb6f5026dd8b74fbefd82ac8, https://github.com/runatlantis/atlantis/pull/6792
**Actions:**
- Fix: Upgrade Atlantis to 0.47.2 or later (patch in commits 8dd22b4 and f04df0d).
- Workaround: Restrict workspace name pattern in `atlantis.yaml` (e.g., alphanumeric only); run Atlantis with minimal privileges; enable plan-only mode for untrusted contributors.
- Tradeoff: Workspace naming restrictions may break existing conventions; plan-only limits automation.
