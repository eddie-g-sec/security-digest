# Security Digest — 2026-10-30

## Cloud Security

The most urgent item is **CVE-2024-53095** in the Linux kernel's SMB/CIFS client (CVSS 9.8 CRITICAL), which affects Kubernetes workloads mounting CIFS shares in non-root network namespaces and can trigger a use-after-free during pod termination, leading to kernel oops and potential container escape. No CISA KEV-confirmed exploits are present in this dataset, so the highest-severity unpatched kernel flaw takes priority. Google Cloud Platform and Docker also carry multiple high-severity issues, including an unauthenticated XSS in Firebase Auth (CVE-2026-85268) and a critical authentication bypass in FearlessCMS's default Docker deployment (CVE-2026-63190).

### Formal Vulnerabilities

#### Google Cloud Platform — CVE-2026-85268 (CVSS UNSCORED UNSCORED)
**Summary:** An unauthenticated remote attacker can execute arbitrary JavaScript in Google Cloud Identity Platform and Firebase Authentication (iOS) by supplying a malicious iOS bundle ID to the auth/handler, exploiting a cross-site scripting flaw in versions prior to 2026-08-14.

**Affected Features / Interoperability:** Firebase Authentication iOS SDK; any iOS application using Firebase Auth with custom bundle ID handling. Downstream impact includes potential session hijacking, credential theft, or malicious actions performed in the context of the authenticated user.

**Source:** https://firebase.google.com/support/releases#auth-helper-fix

**Actions:**
- Fix: Update to Firebase Authentication iOS SDK version released on or after 2026-08-14.
- Workaround: Validate and sanitize bundle IDs client-side before passing to the auth handler; restrict allowed bundle IDs via Firebase console.
- Tradeoff: Client-side validation can be bypassed if the app is compromised; console restrictions may break legitimate multi-bundle deployments.

#### Google Cloud Platform — CVE-2026-93327 (CVSS UNSCORED UNSCORED)
**Summary:** An authenticated attacker can achieve arbitrary code execution in Google Cloud Application Integration by sending a maliciously crafted serialized object to the SubWorkflow task, exploiting a deserialization-of-untrusted-data flaw in versions prior to 2026-09-11. The vulnerability was patched on 11 September 2026 with no customer action required.

**Affected Features / Interoperability:** Application Integration SubWorkflow task; any integration flows that accept serialized objects from untrusted sources. Downstream impact includes potential compromise of the integration runtime and access to connected services.

**Source:** https://docs.cloud.google.com/support/bulletins

**Actions:**
- Fix: Automatic patch applied by Google on 2026-09-11; no customer action needed.
- Workaround: None required.
- Tradeoff: No significant tradeoff.

#### Kubernetes — CVE-2024-53095 (CVSS 9.8 CRITICAL)
**Summary:** A use-after-free in the Linux kernel's SMB/CIFS client (smb: client) occurs when a pod mounting a CIFS share in a non-root network namespace terminates. The kernel socket does not hold a reference count on its network namespace, allowing the namespace to be freed while the socket is still in use during reconnection, triggering a kernel oops and potential privilege escalation.

**Affected Features / Interoperability:** Kubernetes pods using CIFS volumes in non-root network namespaces; any container runtime relying on kernel CIFS client. Downstream impact includes node instability, pod disruption, and potential container escape to host kernel.

**Source:** https://git.kernel.org/stable/c/7e487bbab951f15113edc5061bedf1d4aaf834eb, https://git.kernel.org/stable/c/c7f9282fc27fc36dbaffc8527c723de264a132f8, https://git.kernel.org/stable/c/e8c71494181153a134c96da28766a57bd1eac8cb

**Actions:**
- Fix: Upgrade to a Linux kernel version containing commits 7e487bbab951, c7f9282fc27f, and e8c714941811 (check distribution kernel updates).
- Workaround: Avoid mounting CIFS shares in non-root network namespaces; use hostNetwork: true for pods requiring CIFS (reduces isolation).
- Tradeoff: hostNetwork reduces network isolation between pods and host; may conflict with CNI policies.

#### Kubernetes — CVE-2026-92574 (CVSS 8.8 HIGH)
**Summary:** A CRI-O checkpoint/restore vulnerability allows a user who can create a pod from a malicious checkpointed container to bypass the destination Kubernetes security context. The restored process retains credentials, capabilities, no_new_privs, and seccomp state from the checkpoint instead of enforcing the new configuration, enabling privilege escalation across the container security boundary. Affected: CRI-O 1.34+ and downstream Red Hat OCP 4.17+.

**Affected Features / Interoperability:** CRI-O checkpoint/restore functionality; Kubernetes clusters using CRI-O 1.34+ with checkpointing enabled. Downstream impact includes bypass of PodSecurityPolicies, admission controllers, and runtime security profiles.

**Source:** https://access.redhat.com/security/cve/CVE-2026-92574, https://bugzilla.redhat.com/show_bug.cgi?id=2535436

**Actions:**
- Fix: Upgrade CRI-O to a patched version on supported branches; for Red Hat, update OCP to a version with the fix.
- Workaround: Disable checkpoint/restore functionality if not required; restrict pod creation permissions via RBAC.
- Tradeoff: Disabling checkpoint/restore removes live migration and fast pod startup capabilities.

#### Kubernetes — CVE-2026-119572 (CVSS 8.7 HIGH)
**Summary:** Traefik 3.7.0-ea.1 through 3.7.14 contains an authentication bypass in the Kubernetes Ingress NGINX provider that silently disables mTLS configured via the auth-tls-secret annotation. When another Ingress declares a path on the same host without matching auth-tls settings, Traefik falls back to default TLS options, allowing unauthenticated attackers to reach backends requiring client certificates.

**Affected Features / Interoperability:** Traefik Ingress controller with Kubernetes Ingress NGINX provider using auth-tls-secret annotation. Downstream impact includes exposure of mTLS-protected services to unauthenticated traffic.

**Source:** https://github.com/traefik/traefik/security/advisories/GHSA-p8wx-ph99-xgcr, https://www.vulncheck.com/advisories/traefik-3.7.0-ea.1-before-3.7.15-mtls-bypass-via-ingress-nginx-provider

**Actions:**
- Fix: Upgrade Traefik to 3.7.15 or later.
- Workaround: Ensure all Ingress resources on the same host declare consistent auth-tls-secret annotations; avoid mixing mTLS and non-mTLS paths on the same host.
- Tradeoff: Consistent annotation management increases operational overhead; may require restructuring Ingress topology.

#### Kubernetes — CVE-2026-119115 (CVSS 8.5 HIGH)
**Summary:** Incorrect authorization in the issuer resolution logic of AWS Private CA Connector for Kubernetes (aws-privateca-issuer) before v1.10.1 allows an authenticated remote user to obtain certificates (including subordinate CA certificates) signed by a cluster-scoped AWS Private CA issuer that their approval policy does not authorize.

**Affected Features / Interoperability:** aws-privateca-issuer (cert-manager integration) and AWS Private CA Connector for Kubernetes EKS add-on. Downstream impact includes unauthorized certificate issuance, potential impersonation of services, and PKI trust violation.

**Source:** https://aws.amazon.com/security/security-bulletins/2026-156-aws/, https://github.com/cert-manager/aws-privateca-issuer/releases/tag/v1.10.1, https://github.com/cert-manager/aws-privateca-issuer/security/advisories/GHSA-hjrh-q6pg-mh82

**Actions:**
- Fix: Upgrade aws-privateca-issuer to v1.10.1 or EKS add-on to v1.10.1-eksbuild.1; update any Certificate resources or Ingress annotations referencing the old issuer.
- Workaround: Restrict cluster-scoped issuer permissions via RBAC; use namespace-scoped issuers where possible.
- Tradeoff: Namespace-scoped issuers increase management complexity; RBAC changes may break existing workflows.

#### Kubernetes — CVE-2026-92982 (CVSS 8.5 HIGH)
**Summary:** A Jinja2 template injection vulnerability in Ansible Operator Plugins allows a low-privileged Kubernetes user to execute arbitrary code by crafting malicious custom resource (CR) specification values. The unsanitized values are processed by Ansible within the operator pod, leading to privilege escalation to the operator's service account with cluster-wide permissions.

**Affected Features / Interoperability:** Ansible Operator Plugins processing custom resources; any operator built on the Ansible Operator SDK. Downstream impact includes full cluster compromise via the operator's service account.

**Source:** https://access.redhat.com/errata/RHSA-2026:68695, https://access.redhat.com/errata/RHSA-2026:87120, https://access.redhat.com/errata/RHSA-2026:87124

**Actions:**
- Fix: Apply Red Hat errata RHSA-2026:68695, RHSA-2026:87120, RHSA-2026:87124; update Ansible Operator Plugins to patched versions.
- Workaround: Restrict CR creation/update permissions to trusted users; enable admission webhook validation for CR specs.
- Tradeoff: Admission webhooks add latency and complexity; restricting CR permissions may hinder self-service workflows.

#### Kubernetes — CVE-2026-103314 (CVSS 7.4 HIGH)
**Summary:** Red Hat Advanced Cluster Security for Kubernetes (RHACS) Central SAML authentication endpoint does not retain used SAML assertion or response identifiers, allowing replay attacks. An attacker with a valid, unexpired signed SAML response can submit it multiple times to obtain distinct Central authentication tokens for the mapped identity.

**Affected Features / Interoperability:** RHACS Central SAML authentication (ACS endpoint). Downstream impact includes session hijacking and unauthorized access to RHACS management console.

**Source:** https://access.redhat.com/errata/RHSA-2026:85932, https://access.redhat.com/errata/RHSA-2026:92342, https://access.redhat.com/security/cve/CVE-2026-103314

**Actions:**
- Fix: Apply Red Hat errata RHSA-2026:85932 and RHSA-2026:92342.
- Workaround: Enforce short SAML assertion lifetimes; monitor for repeated SAML response usage.
- Tradeoff: Short assertion lifetimes increase authentication frequency; monitoring requires SIEM integration.

#### Kubernetes — CVE-2026-118760 (CVSS 6.5 MEDIUM)
**Summary:** Kubeflow Pipelines 0.5.1 through 2.17.0 lacks authorization checks on frontend artifact routes, allowing an authenticated user who knows an artifact location to access another tenant's namespace or reach an unguarded direct handler, reading datasets, models, or pipeline outputs in multi-user deployments relying on Kubeflow Pipelines authorization for tenant isolation.

**Affected Features / Interoperability:** Kubeflow Pipelines frontend artifact serving; multi-tenant Kubeflow deployments. Downstream impact includes cross-tenant data leakage of ML artifacts.

**Source:** https://github.com/kubeflow/pipelines/commit/fb69119c997402ebddab4f6410c617cb3d3634ba, https://github.com/kubeflow/pipelines/issues/9889, https://github.com/kubeflow/pipelines/pull/12860

**Actions:**
- Fix: Upgrade to Kubeflow Pipelines 2.17.1 or later (commit fb69119c9974).
- Workaround: Deploy network policies isolating tenant namespaces; avoid sharing artifact store across tenants.
- Tradeoff: Network policies add operational complexity; separate artifact stores increase storage costs.

#### Kubernetes — CVE-2026-119573 (CVSS 4.4 MEDIUM)
**Summary:** Traefik 3.7.11 through 3.7.14 contains an authorization bypass in the Kubernetes Ingress NGINX provider that skips the cross-namespace check on the auth-tls-secret annotation when a cached client authentication TLS option is reused. Users who can create Ingresses can reference another namespace's CA secret already used by another Ingress, enforcing it on their own routes and learning whether it exists (without disclosing contents).

**Affected Features / Interoperability:** Traefik Ingress controller with Kubernetes Ingress NGINX provider using auth-tls-secret annotation and TLS option caching. Downstream impact includes information disclosure of secret existence across namespaces.

**Source:** https://github.com/traefik/traefik/security/advisories/GHSA-28hp-c82p-8vqj, https://www.vulncheck.com/advisories/traefik-3.7.11-before-3.7.15-cross-namespace-authorization-bypass-via-auth-tls-secret

**Actions:**
- Fix: Upgrade Traefik to 3.7.15 or later.
- Workaround: Disable TLS option caching; enforce strict namespace isolation for auth-tls-secret references via admission policy.
- Tradeoff: Disabling caching may increase TLS handshake latency; admission policies require maintenance.

#### Docker — CVE-2026-63190 (CVSS 9.4 CRITICAL)
**Summary:** FearlessCMS prior to 0.1.4 ships five debug/test PHP scripts under `admin/` that perform privileged operations without authentication checks, CSRF protection, or adequate path validation. On PHP's built-in development server (including the default Docker deployment), `router.php` checks an unnormalized admin URI prefix while the filesystem resolves dot segments, allowing `/./admin/` to bypass the login gate and execute debug scripts directly, leading to arbitrary file write and code execution.

**Affected Features / Interoperability:** FearlessCMS default Docker deployment using PHP built-in server; any deployment exposing the admin debug endpoints. Downstream impact includes full container compromise and potential lateral movement.

**Source:** https://github.com/fearlessgeekmedia/FearlessCMS/commit/59fb22cf989b5ba14c387c3212e15b146e02cf9a, https://github.com/fearlessgeekmedia/FearlessCMS/security/advisories/GHSA-3mq8-hrhf-7hv6, https://github.com/fearlessgeekmedia/FearlessCMS/tree/0.1.4

**Actions:**
- Fix: Upgrade to FearlessCMS 0.1.4 or later.
- Workaround: Remove or restrict access to `admin/debug_*.php` scripts; deploy behind a proper web server (nginx/Apache) with normalized URI handling.
- Tradeoff: Removing debug scripts loses debugging capability; switching web servers changes deployment architecture.

#### Docker — CVE-2026-57117 (CVSS 8.8 HIGH)
**Summary:** PraisonAI 4.6.10 through 4.6.58 wraps file operations (read_file, list_files, write_file) into shell command strings using raw path arguments when a compute provider is attached. An attacker who can influence a file-tool path argument can break out of the quoted path and execute arbitrary shell commands in the compute environment (local subprocess or remote).

**Affected Features / Interoperability:** PraisonAI LocalManagedAgent/SandboxedAgent with compute providers; any workflow accepting untrusted file paths. Downstream impact includes container escape and host command execution.

**Source:** https://github.com/MervinPraison/PraisonAI/security/advisories/GHSA-w6h2-fr4q-xvxv, https://github.com/MervinPraison/PraisonAI/security/advisories/GHSA-w6h2-fr4q-xvxv

**Actions:**
- Fix: Upgrade to PraisonAI 4.6.59 or later.
- Workaround: Disable compute providers if not needed; sanitize file path inputs strictly (allowlist characters).
- Tradeoff: Disabling compute providers removes distributed execution capability; strict sanitization may break legitimate paths.

#### Docker — CVE-2026-59179 (CVSS 8.3 HIGH)

**Affected Features / Interoperability:** OpenHop server (`@openhop/server`) API endpoints; any deployment exposing the API without authentication. Downstream impact includes sensitive file disclosure and data destruction.

**Actions:**
- Fix: Upgrade to OpenHop 0.3.7 or later.
- Workaround: Deploy behind an authenticating reverse proxy; restrict filesystem permissions for the server process.
- Tradeoff: Reverse proxy adds infrastructure complexity; filesystem restrictions may break legitimate flow operations.

#### Docker — CVE-2026-119119 (CVSS 7.5 HIGH)

Unauthenticated attackers can send huge values to hold browser pages or stall the rate limiter, exhausting the page pool and blocking other crawls (denial of service).

**Affected Features / Interoperability:** Crawl4AI Docker API server crawl endpoints. Downstream impact includes service unavailability for all crawl jobs.

- Tradeoff: Middleware adds latency; rate limiting may affect legitimate high-volume crawls.
