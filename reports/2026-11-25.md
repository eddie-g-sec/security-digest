### Formal Vulnerabilities

#### Kubernetes — CVE-2026-112788 (CVSS 9.8 CRITICAL)
**Summary:** Missing Authentication for Critical Function in Apache Texera (incubating).



The Python virtual environment (PVE) management endpoints of a computing unit are not authenticated by the application itself. In the local JVM and single-node Docker Compose deployments, which place no authenticating gateway in front of the services, these endpoints are reachable without credentials. The Kubernetes deployment gates them at the gateway, so only the Kubernetes deployment provides the full security model described in SECURITY.md.



This issue affects Apache Texera (incubating): from 1.1.0 through 1.2

**Source:**
- https://lists.apache.org/thread/txzwrypygzpk004m90mg83lonbq3mgvb

#### Kubernetes — CVE-2026-136451 (CVSS 6.8 MEDIUM)
**Summary:** A flaw was found in the Keycloak Operator. Deterministic hashes derived from Kubernetes Secrets are published in generated StatefulSet metadata and in KeycloakOIDCClient status. A user with read access to those resources may be able to recover a low-entropy credential referenced by a Secret, even when Kubernetes RBAC denies the user access to the Secret itself.

#### Docker — CVE-2026-135124 (CVSS UNSCORED)
**Summary:** A race condition during docker cp mount setup in Docker Engine allows a malicious container to leave a read-only bind mount writable while an archive is extracted into the container. When copying files into a container, the daemon bind-mounts the container's volumes into a temporary view and applies the read-only flags afterwards, through a path inside the container's filesystem. A process in the container can change that path in between, so the flags are applied to a different mount and the intended bind mount stays writable for the duration of the copy.

**Source:**
- https://github.com/moby/moby/security/advisories/GHSA-vfmq-r373-x89f
