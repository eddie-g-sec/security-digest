# Security Digest — 2026-11-16

## Cloud Security

The most urgent issue is **CVE-2026-129433** in Dokploy (CVSS 9.9 CRITICAL), an OS command injection allowing authenticated organization members to execute shell commands as root via the `serviceName` parameter during scheduled backups, leading to full host takeover through the mounted Docker socket. No CISA KEV-confirmed exploits are present in this dataset, so the highest-CVSS vulnerability takes precedence.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-129236 (CVSS 7.2 HIGH)
**Summary:** Kubeshark versions 53.1.0 through 53.4.0 allow argument injection via the `pod_regex` parameter in the `start_kubeshark` MCP tool. An attacker who can influence tool arguments (e.g., via an AI agent with `--allow-destructive`) can inject Helm `--set` overrides to redirect privileged container images to an attacker-controlled registry.

**Affected Features / Interoperability:** The `kubeshark mcp` command's `start_kubeshark` tool; impacts Helm chart value overrides for `tap.docker.registry` and `tap.docker.tag`. Downstream: any workloads deployed via the compromised Kubeshark Hub/worker images.

**Source:** https://github.com/kubeshark/kubeshark/commit/a76a1920dc7587be700a17f1592f58a9512ad214, https://github.com/kubeshark/kubeshark/pull/1957, https://github.com/kubeshark/kubeshark/releases/tag/v53.4.0

**Actions:**
- Fix: Upgrade to Kubeshark v53.4.0 or later.
- Workaround: Disable `--allow-destructive` flag or restrict MCP tool access to trusted principals only.
- Tradeoff: Disabling destructive actions limits legitimate administrative automation.

#### Kubernetes — CVE-2026-126643 (CVSS 6.5 MEDIUM)
**Summary:** The AAP Gateway Operator copies a plaintext secret (`controller_resource_server_secret`) from a protected Secret into the `AutomationController` custom resource under `spec.extra_settings`. Although the operator uses `no_log`, the value becomes readable by any principal with read access to the AutomationController CR, bypassing Secret RBAC.

**Affected Features / Interoperability:** AAP Gateway Operator's reconciliation of `AutomationController` resources; exposes `RESOURCE_SERVER.SECRET_KEY` to CR readers. Downstream: any integration relying on that secret's confidentiality.

**Source:** https://access.redhat.com/security/cve/CVE-2026-126643, https://bugzilla.redhat.com/show_bug.cgi?id=2571730

**Actions:**
- Fix: Not specified in available data; monitor Red Hat advisory for patched operator version.
- Workaround: Restrict read access to `AutomationController` CRs via RBAC; avoid storing sensitive values in `spec.extra_settings`.
- Tradeoff: Tighter RBAC may impede legitimate GitOps or monitoring tooling that reads the CR.

#### Kubernetes — CVE-2026-129235 (CVSS 5.3 MEDIUM)
**Summary:** Kubeshark 53.1.0–53.4.0's `download_file` MCP tool writes caller-controlled `dest` paths without confinement, allowing an attacker influencing an AI agent to write arbitrary Hub-supplied bytes to any writable location. Default auth-disabled Hub deployments also expose captured network traffic.

**Affected Features / Interoperability:** `kubeshark mcp` `download_file` tool; impacts local filesystem of the MCP user and Hub API data exposure.

**Source:** https://github.com/kubeshark/kubeshark/commit/a76a1920dc7587be700a17f1592f58a9512ad214, https://github.com/kubeshark/kubeshark/pull/1957, https://github.com/kubeshark/kubeshark/releases/tag/v53.4.0

**Actions:**
- Fix: Upgrade to Kubeshark v53.4.0 or later.
- Workaround: Disable the `download_file` tool or run MCP server with a dedicated, least-privilege user.
- Tradeoff: Disabling the tool removes legitimate file-download functionality for troubleshooting.

#### Kubernetes — CVE-2026-121374 (CVSS UNSCORED UNSCORED)
**Summary:** Checkmk's Kubernetes special agent (<2.5.0p19, <2.4.0p40, 2.3.0 EOL) suffers from argument injection via crafted node roles in the "Exclude nodes based on their role" rule option. A user with rule-edit permission in at least one folder can write files to arbitrary locations as the site user, leading to code execution.

**Affected Features / Interoperability:** Checkmk rule configuration for Kubernetes monitoring; impacts file integrity on the Checkmk site server.

**Source:** https://checkmk.com/werk/17994

**Actions:**
- Fix: Upgrade to Checkmk 2.5.0p19, 2.4.0p40, or later (2.3.0 is EOL).
- Workaround: Restrict rule-edit permissions to trusted administrators only.
- Tradeoff: Limiting rule edits may slow operational changes to monitoring configuration.

#### Kubernetes — CVE-2026-95839 (CVSS UNSCORED UNSCORED)
**Summary:** containerd 2.2.0–2.2.9, 2.3.0–2.3.6, and 2.4.0–2.4.1 can panic and crash when processing an image manifest with a malformed `io.containerd.manifest.subject` annotation digest. In Kubernetes, kubelet retries repeatedly trigger the crash, disrupting container operations on the worker node.

**Affected Features / Interoperability:** containerd daemon's image transfer service; impacts Kubernetes node container runtime stability.

**Source:** https://github.com/containerd/containerd/commit/20a3b31390653d7a83fdaeb0c318b01a263c9d9a, https://github.com/containerd/containerd/commit/2181d7baa2a303ea2082e5c0f1a7697787b61ef2, https://github.com/containerd/containerd/commit/2455fec2f7bfa63adb1f993c63ba0cea9cdedb8c

**Actions:**
- Fix: Upgrade containerd to 2.2.10, 2.3.7, or 2.4.2.
- Workaround: Block pulling of untrusted images; monitor containerd logs for panics and restart daemon if needed.
- Tradeoff: Blocking untrusted images may hinder development workflows; daemon restarts cause brief pod disruption.

#### Docker — CVE-2026-129433 (CVSS 9.9 CRITICAL)
**Summary:** Dokploy before 0.31.1 has an OS command injection in `getComposeContainerCommand()` via the `serviceName` parameter. Authenticated organization members can store shell metacharacters through `backup.create` or `backup.update` tRPC procedures; commands execute as root when scheduled backups run, leveraging the mounted Docker socket for host takeover.

**Affected Features / Interoperability:** Dokploy backup scheduling and Docker Compose command generation; impacts host via Docker socket mount.

**Source:** https://github.com/Dokploy/dokploy, https://github.com/Dokploy/dokploy/blob/v0.31.0/packages/server/src/utils/backups/utils.ts#L152, https://github.com/Dokploy/dokploy/commit/b24006e16e95a10ce3daf739d06ac783e5c70ba0

**Actions:**
- Fix: Upgrade to Dokploy 0.31.1 or later.
- Workaround: Disable scheduled backups or restrict `backup.create`/`backup.update` permissions to highly trusted admins only.
- Tradeoff: Disabling backups removes automated disaster-recovery capability.

#### Docker — CVE-2026-124969 (CVSS 7.1 HIGH)
**Summary:** The Optimole WordPress plugin (≤4.2.19) allows unauthenticated arbitrary file deletion via insufficient path validation in `replace_urls_in_value`. Exploitation requires the PEAR `Archive_Tar` library (common in official WordPress Docker images) and can lead to RCE by deleting critical files like `wp-config.php`.

**Affected Features / Interoperability:** Optimole plugin's media rename/attachment handling; impacts WordPress filesystem integrity.

**Source:** https://plugins.trac.wordpress.org/browser/optimole-wp/tags/4.2.19/inc/media_rename/attachment_db_renamer.php#L319, https://plugins.trac.wordpress.org/browser/optimole-wp/tags/4.2.19/inc/media_rename/attachment_db_renamer.php#L415, https://plugins.trac.wordpress.org/browser/optimole-wp/tags/4.2.19/inc/media_rename/attachment_db_renamer.php#L548

**Actions:**
- Fix: Update Optimole plugin to a version >4.2.19 (specific patched version not specified in data).
- Workaround: Disable or uninstall Optimole plugin until patched; ensure `Archive_Tar` is not loaded if not needed.
- Tradeoff: Plugin removal loses image optimization/CDN features; disabling `Archive_Tar` may break other plugins.

#### Docker — CVE-2026-129237 (CVSS 5.4 MEDIUM)
**Summary:** qbee-agent before 2026.41 has a path-traversal flaw in `unpackTar` extraction: `strings.HasPrefix` check lacks a path-separator boundary, allowing a sibling-prefix traversal when `UseContext` enables Docker Compose build context. A less-privileged archive supplier can create directories/files outside the intended destination.

**Affected Features / Interoperability:** qbee-agent's Docker Compose bundle deployment (`UseContext` feature); impacts host filesystem where agent runs.

**Source:** https://github.com/qbee-io/qbee-agent/commit/eb7875f0a849cb33325956d0b75e27061d7a7fa3, https://github.com/qbee-io/qbee-agent/pull/148, https://github.com/qbee-io/qbee-agent/releases/tag/2026.41

**Actions:**
- Fix: Upgrade to qbee-agent 2026.41 or later.
- Workaround: Disable `UseContext` for Docker Compose bundles or restrict archive upload to trusted sources.
- Tradeoff: Disabling `UseContext` removes the ability to use build contexts in Compose deployments.

#### Docker — CVE-2026-126943 (CVSS 4.9 MEDIUM)
**Summary:** Zipline 4.2.0–4.6.1 logs sensitive environment variables (e.g., `OAUTH_OIDC_CLIENT_SECRET`) without redaction at startup. Attackers with access to system journal or Docker logs can steal OAuth2 client secrets and exchange intercepted callbacks for valid tokens.

**Affected Features / Interoperability:** Zipline startup logging; impacts OAuth2/OIDC authentication security.

**Source:** https://github.com/diced/zipline/security/advisories/GHSA-2h25-m8rf-v86j, https://www.vulncheck.com/advisories/zipline-4.2.0-before-4.6.2-oauth2-client-secret-leakage-in-startup-logs

**Actions:**
- Fix: Upgrade to Zipline 4.6.2 or later.
- Workaround: Restrict log access (system journal, Docker logs) to trusted personnel; rotate OAuth2 client secrets if exposure suspected.
- Tradeoff: Log restriction may hinder debugging; secret rotation requires coordinated client updates.

#### Docker — CVE-2026-112182 (CVSS UNSCORED UNSCORED)
**Summary:** OpenKM Community Edition's REST endpoints `registerProcessDefinition` and `runProcessDefinition` lack role verification. An authenticated user with `ROLE_USER` can register and execute BeanShell scripts, achieving Java/OS command execution as the service user (root in the official Docker image).

**Affected Features / Interoperability:** OpenKM workflow definition management; impacts host via Docker container running as root.

**Source:** https://www.incibe.es/en/incibe-cert/notices/aviso/multiple-vulnerabilities-openkm-community-edition

**Actions:**
- Fix: Not specified in available data; monitor OpenKM/INCIBE advisories for patch.
- Workaround: Remove `ROLE_USER` from untrusted accounts; run OpenKM container as non-root user.
- Tradeoff: Running as non-root may break file-permission expectations; role removal limits legitimate workflow usage.

#### Docker — CVE-2026-115538 (CVSS UNSCORED UNSCORED)
**Summary:** Moby's overlay network driver fails to restore iptables rules for encrypted overlay networks after firewalld reloads/starts. Outgoing VXLAN datagrams bypass IPsec encryption, and incoming cleartext VXLAN traffic is accepted. Condition persists until the encrypted network's last local endpoint is removed and re-added, or dockerd restarts.

**Affected Features / Interoperability:** Docker Engine encrypted overlay networking with firewalld; impacts confidentiality and integrity of inter-node container traffic.

**Source:** https://github.com/moby/moby/security/advisories/GHSA-6jhp-7446-hf7f

**Actions:**
- Fix: Not specified in available data; monitor Moby/Docker Engine releases for patch.
- Workaround: Avoid firewalld reloads on nodes with encrypted overlay networks; restart dockerd after any firewalld change.
- Tradeoff: Avoiding firewalld reloads may delay firewall policy updates; dockerd restart disrupts all containers on the node.

#### Terraform — CVE-2026-91879 (CVSS 8.8 HIGH)
**Summary:** Dell Terraform providers for ObjectScale (versions prior to 1.1.1) and PowerStore (versions 1.2.1 through 1.3.0) log sensitive information during client initialization. A low-privileged remote attacker could exploit this to gain information exposure and unauthorized access.

**Affected Features / Interoperability:** Terraform provider client initialization logging; impacts credential/secrecy in Terraform logs.

**Source:** https://www.dell.com/support/kbdoc/en-in/000515434/dsa-2026-433-security-update-for-dell-terraform-provider-for-dell-storage-multiple-vulnerabilities

**Actions:**
- Fix: Upgrade ObjectScale provider to 1.1.1+; upgrade PowerStore provider to version after 1.3.0 (exact version not specified).
- Workaround: Mask or redact Terraform logs in CI/CD pipelines; restrict access to Terraform state/logs.
- Tradeoff: Log redaction may hinder troubleshooting; access restriction may impede collaboration.
