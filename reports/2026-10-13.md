# Security Digest — 2026-10-13

## Database

One-paragraph executive summary, highlighting the single most urgent item (a CISA KEV-confirmed entry always outranks a merely high-CVSS entry, since it's confirmed exploitation vs. theoretical severity).

Among the database assets, the most urgent issue is CVE‑2025‑56157, a critical (CVSS 9.8) vulnerability in Dify’s Docker‑based PostgreSQL deployment that exposes default credentials when the database port is exposed, enabling any network attacker to gain full database access.

### Formal Vulnerabilities

#### MySQL — CVE-2025-50455 (CVSS 9.1 CRITICAL)
**Summary:** SQL injection via the order_by parameter of the /customers/search endpoint in EasyAppointments ≤ 1.5.1. Unauthenticated attackers can supply a malicious order_by value, causing time‑based queries, schema enumeration, and potentially remote code execution by writing a PHP shell with INTO OUTFILE when MySQL permits file writing.  
**Affected Features / Interoperability:** The web application’s search endpoint and its dynamic ORDER BY clause; exploitation can break application integrity, lead to data leakage, and compromise the underlying server.  
**Source:** https://github.com/threatlance-org/security-advisories/blob/main/CVE-2025-50455/advisory.md, https://github.com/threatlance-org/security-advisories/blob/main/CVE-2025-50455/poc.py, https://www.linkedin.com/posts/michael-chesang_cve-securityadvisory-appsec-activity-7360754900827365376-Z-IY, https://github.com/threatlance-org/security-advisories/blob/main/CVE-2025-50455/advisory.md  
**Actions:**  
- Fix: Upgrade EasyAppointments to a version that sanitizes the order_by parameter (no specific version listed; consider the latest release if available).  
- Workaround: Implement strict input validation on the order_by field, restrict allowed column names, and disable file‑write capabilities in MySQL (e.g., set `secure_file_priv` to a safe directory) to prevent PHP shell creation.  
- Tradeoff: The workaround may limit legitimate ordering options and could affect existing functionality that relies on dynamic ORDER BY.

#### MySQL — CVE-2026-107815 (CVSS 8.5 HIGH)
**Summary:** A boundary check flaw in MariaDB’s CONNECT engine’s DOS table type permits a one‑byte null write beyond a stack buffer when an authenticated user triggers a malformed DOS table, leading to crash or remote code execution.  
**Affected Features / Interoperability:** The CONNECT storage engine’s DOS table handling; impact may disrupt replication, client connections, and overall database availability.  
**Source:** https://github.com/MariaDB/server/commit/b369925f6855d3e1f0ebcf453492724b99fda6f8, https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19, https://github.com/MariaDB/server/releases/tag/mariadb-10.6.28, https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13, https://github.com/MariaDB/server/releases/tag/mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade MariaDB to version 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, or 13.0.2.  
- Workaround: Disable the CONNECT engine if not needed, or rebuild the server with the patch applied.  
- Tradeoff: Disabling CONNECT may remove support for certain storage features; rebuilding requires custom compilation and testing.

#### MySQL — CVE-2026-107818 (CVSS 8.4 HIGH)
**Summary:** The mariadb.service unit writes a file at /run/mysqld/wsrep-new-cluster during restart. A database user with FILE privilege and a permissive secure-file-priv can create that file with attacker‑controlled environment values, leading to code execution when the service restarts.  
**Affected Features / Interoperability:** The systemd service unit for MariaDB; exploitation can affect replication and any services that rely on the wsrep cluster restart.  
**Source:** https://github.com/MariaDB/server/commit/e3d62d4e78fd4941cef3f5053e6a50d0b32d740e, https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19, https://github.com/MariaDB/server/releases/tag/mariadb-10.6.28, https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13, https://github.com/MariaDB/server/releases/tag/mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade to MariaDB versions 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, or 13.0.2.  
- Workaround: Restrict FILE privilege, ensure secure-file-priv does not allow writes to /run/mysqld, or remove write permission on that directory.  
- Tradeoff: Limiting FILE privilege may impede legitimate backup or dump operations; removing write access could break maintenance scripts.

#### MySQL — CVE-2026-109573 (CVSS 8.1 HIGH)
**Summary:** In phpMyFAQ before 4.1.9, the PdoMysql::escape() function fails to properly handle Unicode right single quotation marks when NO_BACKSLASH_ESCAPES mode is enabled, allowing unauthenticated attackers to inject SQL via the search parameter of the autocomplete API.  
**Affected Features / Interoperability:** The search autocomplete endpoint of phpMyFAQ; exploitation can lead to credential disclosure, record modification, or table deletion.  
**Source:** https://github.com/thorsten/phpMyFAQ/security/advisories/GHSA-98p2-cg7p-h385, https://www.vulncheck.com/advisories/phpmyfaq-before-4.1.9-sql-injection-via-api-autocomplete-search-endpoint, https://github.com/thorsten/phpMyFAQ/security/advisories/GHSA-98p2-cg7p-h385  
**Actions:**  
- Fix: Upgrade phpMyFAQ to version 4.1.9 or later.  
- Workaround: Disable NO_BACKSLASH_ESCAPES mode or sanitize user‑supplied search terms before they reach the API.  
- Tradeoff: Disabling NO_BACKSLASH_ESCAPES may affect other query behaviors; sanitization adds processing overhead.

#### MySQL — CVE-2026-107821 (CVSS 8.0 HIGH)

**Affected Features / Interoperability:** Binary FRM file handling; impact may disrupt database operation and cause downtime for all connected clients.  
**Source:** https://github.com/MariaDB/server/commit/3b1c2e58abab5571bec4ff52773ddc75b1738da9, https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19, https://github.com/MariaDB/server/releases/tag/mariadb-10.6.28, https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13, https://github.com/MariaDB/server/releases/tag/mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade MariaDB to version 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, or 13.0.2.  
- Workaround: Restrict write access to the data directory, enforce filesystem permissions, and monitor for unexpected FRM file creation.  
- Tradeoff: Tightening filesystem permissions may hinder legitimate file operations or backup processes.

#### PostgreSQL — CVE-2025-56157 (CVSS 9.8 CRITICAL)
**Summary:** Default PostgreSQL credentials are shipped in Dify Docker compose files up to version 1.5.1; if the container exposes port 5432, any network user can log in with the published username and password, gaining full database access.  
**Affected Features / Interoperability:** Direct database access via PostgreSQL; compromise can lead to data breach, unauthorized modifications, and further attacks on connected services.  
**Source:** https://gist.github.com/Cristliu/216ddbadaf3258498c93d408683ecabd, https://gist.github.com/Cristliu/298f51cbc72c45d91632cd0d65aa8161, https://github.com/langgenius/dify, https://github.com/langgenius/dify/issues/15285, https://github.com/langgenius/dify/pull/15286  
**Actions:**  
- Fix: Upgrade Dify to version 1.0.1 or later, or reconfigure Docker compose to avoid exposing port 5432.  
- Workaround: Change the default credentials to strong, unique values and restrict network access to the PostgreSQL port via firewall rules.  
- Tradeoff: Changing credentials may require updating application configuration; firewall restrictions could impede legitimate remote access.

#### PostgreSQL — CVE-2025-14180 (CVSS 7.5 HIGH)
**Summary:** In PHP PDO PostgreSQL driver versions before the patched releases, an invalid character sequence in a prepared statement can cause the quoting function to return NULL, leading to a null‑pointer dereference and potential server crash.  
**Affected Features / Interoperability:** PHP applications using PDO with PostgreSQL; the issue affects availability of the database server when such statements are sent.  
**Source:** https://github.com/php/php-src/security/advisories/GHSA-8xr5-qppj-gvwj  
**Actions:**  
- Fix: Upgrade PHP to version 8.1.34+, 8.2.30+, 8.3.29+, 8.4.16+, or 8.5.1+ to apply the driver fix.  
- Workaround: Disable the PDO::ATTR_EMULATE_PREPARES option or avoid sending invalid character sequences in prepared statements.  
- Tradeoff: Disabling emulation may alter statement behavior; avoiding invalid characters may limit certain query patterns.

#### PostgreSQL — CVE-2026-109954 (CVSS 6.5 MEDIUM)
**Summary:** Parse Server versions before 8.6.96 (and 9.0.0 before 9.10.2‑alpha.5) share transactional batch state across concurrent requests, causing other clients’ acknowledged writes to be rolled back and PostgreSQL transactions to remain open, leading to write failures.  
**Affected Features / Interoperability:** Transactional batch requests in Parse Server; impacts PostgreSQL and MongoDB replica sets and sharded clusters, causing denial of service for write operations.  
**Source:** https://github.com/parse-community/parse-server/security/advisories/GHSA-jhh9-hrgh-c9gv, https://www.vulncheck.com/advisories/parse-server-9.0.0-before-9.10.2-alpha.5-transactional-batch-request-write-interference  
**Actions:**  
- Fix: Upgrade Parse Server to version 8.6.96 or later (or 9.10.2‑alpha.5+).  
- Workaround: Throttle batch request rates and implement client‑side retry logic for write operations.  
- Tradeoff: Throttling may increase latency for clients but prevents write rollbacks.

#### MongoDB — CVE-2026-109426 (CVSS 7.5 HIGH)
**Summary:** Telegram‑Stremio stores operator session strings in MongoDB using a reversible, keyless encoding; attackers with DB access can decode the string and obtain a fully authenticated Telegram session, bypassing two‑step verification.  
**Affected Features / Interoperability:** Session storage mechanism; compromise enables full account takeover and unauthorized messaging, affecting user privacy and service integrity.  
**Source:** https://gist.github.com/mansurmavlankulov/489554cad7b38e07b9651c217f00fffb, https://www.vulncheck.com/advisories/telegram-stremio-insecure-session-storage-via-encode-string  
**Actions:**  
- Fix: Replace the reversible encoding with strong encryption and rotate session tokens; update the application to use proper credential storage.  
- Workaround: Limit MongoDB access to only trusted services, rotate session tokens regularly, and monitor for unauthorized access to the database.  
- Tradeoff: Enhanced security may require operational changes to token management and increased monitoring overhead.

#### MongoDB — CVE-2026-104004 (CVSS 6.5 MEDIUM)
**Summary:** MongoDB Server’s collection validation feature may mishandle certain validator expressions, causing the server process to crash when a document is later inserted, affecting authenticated write users.  
**Affected Features / Interoperability:** Collection validation logic; potential server crash can disrupt all database operations for users relying on that collection.  
**Source:** https://jira.mongodb.org/browse/SERVER-131412  
**Actions:**  
- Fix: Upgrade MongoDB Server to a version that resolves the validation expression handling issue (version not specified).  
- Workaround: Avoid using problematic validation expressions in collection definitions; test inserts in a staging environment before production deployment.  
- Tradeoff: Limiting validation expressions may reduce data integrity safeguards but prevents crashes.

#### MongoDB — CVE-2026-104005 (CVSS 6.5 MEDIUM)

**Affected Features / Interoperability:** Sharded cluster routing; a crash in mongos can interrupt query processing for all connected clients, causing service outage.  
**Source:** https://jira.mongodb.org/browse/SERVER-131411  
**Actions:**  
- Fix: Upgrade mongos to a patched version (exact version not specified).  
- Workaround: Restrict aggregation pipeline usage to authorized users, disable unsafe internal stages, and monitor mongos logs for abnormal restarts.  
- Tradeoff: Limiting pipeline capabilities may reduce flexibility for legitimate administrative tasks.
