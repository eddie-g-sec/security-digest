# Security Digest — 2026-11-02

## Cloud Security

Executive summary: No CISA KEV-confirmed entries were found in today's digest. The single most urgent item is CVE-2026-120306 (Beta9, CVSS 9.9, CRITICAL), a privilege escalation vulnerability in the Beta9 build worker that allows container escape and root-level access on the host. This affects both Kubernetes and Docker environments using Beta9 for tenant image builds.

### Formal Vulnerabilities

#### AWS — CVE-2026-115812 (CVSS 9.8 CRITICAL)
**Summary:** Relative path traversal during model archive extraction in AWS Multi Model Server 1.1.11 and earlier allows remote actors to execute arbitrary code via a crafted model archive. Multi Model Server is end of life with no fixed version available; users should discontinue use and migrate to a supported model serving solution.

**Affected Features / Interoperability:** Model archive extraction and model serving pipeline components. Downstream impacts include broken ML workload serving and potential exposure of sensitive model artifacts.

**Source:** https://aws.amazon.com/security/security-bulletins/2026-148-aws/

**Actions:**
- Fix: No fixed version available; Multi Model Server is end of life
- Workaround: Discontinue use of Multi Model Server and migrate to a supported model serving solution
- Tradeoff: Migration effort required; no significant tradeoff from workaround itself

#### Microsoft Azure — CVE-2026-105769 (CVSS 9.3 CRITICAL)
**Summary:** kaniko before 1.25.20 can send a Microsoft Entra ID (Azure AD) access token for Azure Resource Manager to an attacker-controlled registry host. The credential helper uses an unanchored regex that accepts any hostname containing .azurecr.io, .azurecr.cn, .azurecr.de, or .azurecr.us.

**Affected Features / Interoperability:** Azure Container Registry credential helper and kaniko build process. Downstream impacts include broken container build isolation and potential credential leakage to attacker-controlled registries.

**Source:** https://github.com/chainguard-forks/kaniko/pull/495, https://github.com/chainguard-forks/kaniko/releases/tag/v1.25.20, https://github.com/chainguard-forks/kaniko/security/advisories/GHSA-5q7h-w9jf-cx97

**Actions:**
- Fix: Upgrade kaniko to v1.25.20 or later
- Workaround: Restrict network access to Azure Container Registry hosts; avoid using the affected credential helper
- Tradeoff: May require infrastructure changes to restrict registry access

#### Kubernetes — CVE-2026-120306 (CVSS 9.9 CRITICAL)
**Summary:** Beta9 turns each shell command in a tenant image definition into a Dockerfile RUN line executed with Buildah on the build worker. The worker sets BUILDAH_ISOLATION=chroot without passing --isolation, keeping PID, network, IPC, and user namespaces while running as uid 0 with CAP_DAC_OVERRIDE. PID 1 in procfs is the worker entrypoint, making /proc/1/root writable, containing runc, buildah, and runsc binaries.

**Affected Features / Interoperability:** Tenant image building, Buildah isolation, worker container filesystem. Downstream impacts include complete container escape, host root compromise, and cluster-wide impact.

**Source:** https://github.com/beam-cloud/beta9, https://github.com/beam-cloud/beta9/commit/a28bf12cf0007c792a25d8ed282b4e8bf6f30393, https://github.com/beam-cloud/beta9/pull/1897

**Actions:**
- Fix: Upgrade Beta9 to a patched version (specific version not specified in data)
- Workaround: Disable tenant image building or use alternative build tools
- Tradeoff: Disabling tenant builds may break CI/CD pipelines

#### Kubernetes — CVE-2026-120307 (CVSS 9.9 CRITICAL)
**Summary:** The Beta9 worker serves the sandbox file API from outside the container. getHostPathFromContainerPath turns the tenant's container path into a worker path. If the unresolved path starts with a mount destination (including default upload mount at /tmp/.beta9), the remainder is joined onto that mount's source with filepath.Join, which cleans parent-directory segments after the prefix check. A long enough run of those segments names any absolute path on the worker. A path matching no mount is joined onto the container root and opened in the worker's own filesystem, allowing absolute symbolic links.

**Affected Features / Interoperability:** Sandbox file API, getHostPathFromContainerPath, worker filesystem. Downstream impacts include arbitrary file read/write on the worker host, breaking sandbox isolation.

**Source:** https://github.com/beam-cloud/beta9, https://github.com/beam-cloud/beta9/commit/a28bf12cf0007c792a25d8ed282b4e8bf6f30393, https://github.com/beam-cloud/beta9/pull/1897

**Actions:**
- Fix: Upgrade Beta9 to a patched version (specific version not specified in data)
- Workaround: Restrict file API access or disable sandbox file operations
- Tradeoff: May break legitimate file operations within sandboxes

#### Kubernetes — CVE-2026-20770 (CVSS 6.7 MEDIUM)

System software adversary with a privileged user combined with low complexity attack may enable escalation of privilege.

**Affected Features / Interoperability:** User applications, Ring 3 protection mechanisms. Downstream impacts include privilege boundary violations affecting confidentiality, integrity, and availability.

**Source:** https://intel.com/content/www/us/en/security-center/advisory/intel-sa-01460.html

**Actions:**

- Workaround: Review and tighten privilege boundaries on affected user applications
- Tradeoff: Minimal; workaround focuses on access control review

#### Kubernetes — CVE-2026-63121 (CVSS 6.3 MEDIUM)
**Summary:** Kubewarden policies' trusted-repos-policy compares an image's registry hostname against reject/allow lists case-sensitively even though DNS names are case-insensitive. An image with an uppercase or mixed-case registry hostname can miss a rejection rule for the equivalent lowercase host, so the admission policy accepts a resource whose container runtime pulls the same prohibited image. Only reject-list configuration is affected.

**Affected Features / Interoperability:** Kubewarden admission policy, container runtime image pulls. Downstream impacts include admission control bypass allowing prohibited images to be deployed.

**Source:** https://github.com/kubewarden/policies/commit/bc5597fcbbb0bc464b714ca7ff645c9743dea41b, https://github.com/kubewarden/policies/security/advisories/GHSA-8p62-9vh2-272p, https://github.com/kubewarden/policies/tree/trusted-repos-policy/v2.1.2

**Actions:**
- Fix: Upgrade Kubewarden policies to v2.1.2 or later
- Workaround: Normalize registry hostnames to lowercase before admission checks
- Tradeoff: Requires policy configuration changes

#### Kubernetes — CVE-2026-62284 (UNSCORED)
**Summary:** OSAC operator's console-proxy RemoteConfigResolver parses Kubernetes Secret kubeconfig data with clientcmd.RESTConfigFromKubeConfig without sanitizing the resulting rest.Config. An attacker who can create or modify a Secret labeled osac.openshift.io/remote-cluster-kubeconfig: "true" in a namespace where the proxy's RoleBinding grants Secret read access can supply users[].user.exec. When rest.TransportFor builds the HTTP transport for an upstream WebSocket connection, client-go invokes that exec credential.

**Affected Features / Interoperability:** console-proxy, RemoteConfigResolver, kubeconfig parsing, WebSocket upstream connections. Downstream impacts include arbitrary command execution via exec credential injection.

**Source:** https://github.com/osac-project/osac-operator/commit/7e4222b6ab465fc00606c8cfed980b226820cb1b, https://github.com/osac-project/osac-operator/commit/86466378aa3603253dca7fa2f59a2733af0dc092, https://github.com/osac-project/osac-operator/pull/321

**Actions:**
- Fix: Upgrade OSAC operator to a patched revision (specific revision not specified in data)
- Workaround: Restrict RoleBinding read access to Secrets labeled osac.openshift.io/remote-cluster-kubeconfig: "true"; audit existing configurations
- Tradeoff: May limit legitimate remote cluster configuration management

#### Docker — CVE-2026-120203 (CVSS 8.8 HIGH)
**Summary:** ShowDoc 2.8.14 before 3.9.6 contains a code injection vulnerability in its Mock feature that allows authenticated users to execute shell commands through mockjs templates. Attackers can store a template via MockController::add with escaped parentheses that mockjs evaluates with eval(), then trigger it through MockController::infoByKey to run commands, as root in the official Docker image.

**Affected Features / Interoperability:** ShowDoc Mock feature, mockjs template evaluation. Downstream impacts include arbitrary command execution as root within the Docker image.

**Source:** https://gist.github.com/LioTree/028af150fd991cf9924dd2c7d5912e54, https://github.com/star7th/showdoc, https://github.com/star7th/showdoc/blob/v3.9.5/mock/index.js#L42

**Actions:**
- Fix: Upgrade ShowDoc to 3.9.6 or later
- Workaround: Disable the Mock feature or restrict template evaluation
- Tradeoff: Disabling Mock may break documentation generation features

#### Docker — CVE-2026-120460 (CVSS 8.8 HIGH)
**Summary:** Jpom through 2.11.12 contains a cross-workspace authorization bypass vulnerability that allows authenticated users to manage other workspaces' Docker hosts by supplying foreign Docker asset ids. Attackers with Docker permission in any workspace can control containers, images, volumes, and networks, including creating privileged containers with host bind mounts.

**Affected Features / Interoperability:** DockerContainerController, DockerImagesController, workspace isolation. Downstream impacts include complete control over Docker resources across workspaces and ability to create privileged containers with host bind mounts.

**Source:** https://github.com/dromara/Jpom/blob/v2.11.12/modules/server/src/main/java/org/dromara/jpom/controller/docker/DockerContainerController.java#L48-L51, https://github.com/dromara/Jpom/blob/v2.11.12/modules/server/src/main/java/org/dromara/jpom/controller/docker/DockerImagesController.java#L48-L51, https://github.com/dromara/Jpom/commit/ff09fe8095a792cea9c4b8babd93a333655d0a28

**Actions:**
- Fix: Upgrade Jpom to 2.11.12 or later
- Workaround: Implement workspace-scoped Docker permissions and validate asset ownership
- Tradeoff: Requires permission model redesign

#### Docker — CVE-2026-59177 (CVSS 8.8 HIGH)
**Summary:** ESPHome Device Builder Dashboard prior to 1.0.10 has the Home Assistant add-on's trusted ingress site bind to 0.0.0.0 while intentionally skipping dashboard authentication because the supervisor is expected to authenticate requests upstream. Host networking, required for mDNS, also binds this no-auth site to the Home Assistant host's LAN interface. Any device on that local network can connect directly to the ingress port, bypass the supervisor, and obtain the full dashboard without credentials.

**Affected Features / Interoperability:** Home Assistant add-on ingress site, supervisor authentication, host networking/mDNS. Downstream impacts include unauthenticated access to the full dashboard from any LAN device.

**Source:** https://github.com/esphome/device-builder/commit/b6387db3f8bf1d3df5771f40e9856b959ae4f6a1, https://github.com/esphome/device-builder/pull/1565, https://github.com/esphome/device-builder/releases/tag/1.0.10

**Actions:**
- Fix: Upgrade ESPHome Device Builder Dashboard to 1.0.10 or later
- Workaround: Bind ingress site to localhost only; restrict LAN access
- Tradeoff: May break mDNS functionality or local device discovery

#### Docker — CVE-2026-77055 (UNSCORED)
**Summary:** boneIO black_debian_images gives the boneio service account excessive privileges, including full passwordless sudo access and membership in the docker group. A local attacker who compromises the boneio user can use these privileges to escalate to root.

**Affected Features / Interoperability:** boneio service account, sudoers rules, docker group membership. Downstream impacts include root escalation from a compromised service account.

**Source:** https://boneio.eu/en/docs/black, https://cert.pl/en/posts/2026/10/CVE-2026-77052

**Actions:**
- Fix: Upgrade boneIO to 1.6.0 or later (removes sudoers rule and docker group membership when sealed)
- Workaround: Remove sudoers rule and docker group membership manually; migrate privileged operations to helpers accepting only fixed commands
- Tradeoff: Privileged operations may require additional helper scripts
