# Security Digest — 2026-10-26

## Cloud Security

This week's cloud security landscape is dominated by multiple critical vulnerabilities across Kubernetes, Docker, and cloud-native tooling, with several CVSS 10.0 and 9.9 issues enabling unauthenticated remote code execution. The most urgent item is **CVE-2026-83938** in Azure Kubernetes Configuration Service, a CVSS 10.0 flaw allowing unauthenticated privilege escalation over the network, though it lacks CISA KEV confirmation. However, the broader ecosystem shows systemic risks: hardcoded secrets in SOCFortress CoPilot (CVE-2026-42869), unauthenticated RCE in OpenHands SDK (CVE-2026-112346), and container escape via Gitea act_runner (CVE-2026-58053) all demand immediate attention. Organizations running self-hosted Kubernetes, Docker-based CI/CD, or cloud-native development platforms should prioritize patching these critical issues immediately.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-46389 (CVSS 10.0 CRITICAL) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** A logic error in the `client-kubernetes-secret` Keycloak client authenticator in UDS Identity Config (versions 0.11.0–0.26.0) causes submitted `client_secret` values to be overwritten with a mounted Kubernetes secret before comparison, allowing an attacker who knows a `client_id` to authenticate as that client with any `client_secret`. This vulnerability is confirmed as actively exploited by CISA KEV.

**Affected Features / Interoperability:** Impacts Keycloak-based identity management in UDS Core deployments, affecting authentication flows for all services relying on UDS-managed identity providers. Downstream impacts include unauthorized access to Kubernetes clusters, service meshes, and any application integrated with the Keycloak identity provider.

**Source:**
- https://github.com/defenseunicorns/uds-identity-config/releases/tag/v0.26.1
- https://github.com/defenseunicorns/uds-identity-config/security/advisories/GHSA-8mg2-6588-r4hw

**Actions:**
- Fix: Upgrade to UDS Identity Config version 0.26.1 or later
- Workaround: Rotate all Keycloak client secrets and audit authentication logs for suspicious activity
- Tradeoff: No significant tradeoff
