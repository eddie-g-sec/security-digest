Scoped Vulnerability Tracking

Cloud Security

No CISA KEV-confirmed entries appear in the supplied formal vulnerability data, so the most urgent item is the highest-impact critical issue: CVE-2026-127073 in OpsTree BuildPiper before 2.7.0 (CVSS 9.9). An authenticated project user can submit an unrestricted Kubernetes manifest through the Additional Manifest feature and have the pipeline apply it with cluster-wide credentials, enabling creation of a ClusterRoleBinding to `cluster-admin` and full control of workloads and secrets. The rest of today’s cloud-scope set is dominated by critical Kubernetes and Docker/container-platform issues, including additional BuildPiper privilege and isolation bypasses, GPUStack and Telepresence authorization gaps, and multiple containerized application RCE or secret-exposure flaws.

Formal Vulnerabilities

AWSCVE-2026-121686CVSS 9.8 · CRITICAL

Summary: FrodoBots EarthRover Mini+ firmware versions 6.2.4_6.2.5_0.614.0 accept arbitrary shell commands via AWS IoT MQTT messages and execute them as root. Access is gated only by shared IoT credentials, with no per-device authentication, so compromise of those credentials can enable remote code execution across the fleet.

Affected Features / Interoperability: The firmware’s MQTT command-handling method and AWS IoT MQTT integration are affected. Downstream impact includes fleet-wide device control and any telemetry or management workflows that rely on the shared IoT credential model; the raw data does not specify additional integrations.

Source: https://github.com/frodobots-org ; https://kb.cert.org/vuls/id/188754 ; https://www.frodobots.ai/

Actions:

  • Fix: No fixed firmware version is stated in the provided data.
  • Workaround: Rotate and tightly scope AWS IoT credentials, restrict MQTT ingress to trusted brokers/networks, and monitor command topics for unexpected shell payloads.
  • Tradeoff: Restricting MQTT paths or credentials can disrupt fleet telemetry and remote management.
KubernetesCVE-2026-127073CVSS 9.9 · CRITICAL

Summary: OpsTree BuildPiper before 2.7.0 allows project users to submit unrestricted Kubernetes manifests through the Additional Manifest feature. Because the pipeline applies them with cluster-wide credentials, an attacker can deploy a ClusterRoleBinding that grants a service account `cluster-admin`, taking control of all workloads and secrets.

Affected Features / Interoperability: The BuildPiper Additional Manifest feature and its pipeline service-account permissions are affected. Downstream impact includes Kubernetes RBAC, workload orchestration, and secret access across the cluster.

Source: https://gist.github.com/neelkotnis/7bc715e190e5be2c2fc5be15c4035ce7 ; https://www.buildpiper.io/ ; https://www.vulncheck.com/advisories/opstree-buildpiper-before-2.7.0-privilege-escalation-via-additional-manifest

Actions:

  • Fix: Upgrade BuildPiper to 2.7.0 or later.
  • Workaround: Disable or restrict the Additional Manifest feature to trusted administrators and enforce admission policies that block ClusterRoleBindings to `cluster-admin`.
  • Tradeoff: Restricting manifests can break legitimate pipeline-driven deployments.
KubernetesCVE-2026-127080CVSS 9.9 · CRITICAL

Summary: OpsTree BuildPiper before 2.7.0 allows authenticated deploy users to define arbitrary Kubernetes `hostPath` volumes without allow-list or policy checks. Setting the host path to `/` can mount the worker node root filesystem read-write, breaking container isolation and enabling node and cluster compromise.

Affected Features / Interoperability: The Define HostPath Volume configuration and BuildPiper deployment pipeline are affected. Downstream impact includes container isolation, node filesystem integrity, and cluster-wide compromise potential.

Source: https://gist.github.com/neelkotnis/b8c1cf47f829c28086fe78d8187eb938 ; https://www.buildpiper.io/ ; https://www.vulncheck.com/advisories/opstree-buildpiper-before-2.7.0-container-escape-via-unrestricted-hostpath-volumes

Actions:

  • Fix: Upgrade BuildPiper to 2.7.0 or later.
  • Workaround: Enforce admission policies that deny `hostPath` volumes, especially `/`, and restrict deploy-user permissions.
  • Tradeoff: Denying `hostPath` can break workloads that legitimately need node-level access.
KubernetesCVE-2026-103002CVSS 8.8 · HIGH

Summary: GPUStack 2.2.0 through before 2.2.2 forwards authenticated non-administrator requests to a selected Kubernetes cluster without a resource-level authorization check. The proxy uses a reachable worker’s Kubernetes ServiceAccount credentials, so a caller can read sensitive resources or create, modify, or delete workloads according to that account’s permissions.

Affected Features / Interoperability: The `cluster_apiserver_proxy` component and Kubernetes-provider cluster integration are affected. Downstream impact includes Kubernetes resource access, workload orchestration, and any permissions granted to the worker ServiceAccount.

Source: https://github.com/gpustack/gpustack/commit/363191fa1da7e1426c6041f78b3cf00aff2622fe ; https://github.com/gpustack/gpustack/commit/cdd67467e0f314609dc82216e142940d321abfed ; https://github.com/gpustack/gpustack/pull/5911

Actions:

  • Fix: Upgrade GPUStack to 2.2.2 or later.
  • Workaround: Restrict access to `cluster_apiserver_proxy` to administrators and apply network policies limiting which pods can reach it.
  • Tradeoff: Restricting the proxy can limit non-admin cluster visibility and management workflows.
KubernetesCVE-2026-102340CVSS 8.5 · HIGH

Summary: Telepresence before 2.31.0 exposes the Traffic Manager gRPC API on port 8081 to unauthenticated cluster-network callers. An attacker with any pod that can reach the manager can register in an arbitrary managed namespace, create service intercepts, receive intercepted traffic, and obtain victim pod data.

Affected Features / Interoperability: The Traffic Manager gRPC API, `ArriveAsClient`, and `CreateIntercept` paths are affected. Downstream impact includes service interception, namespace isolation, and pod traffic confidentiality.

Source: https://github.com/telepresenceio/telepresence/commit/04ec3464fe8878fdc96420cdc8036edefa0dc9ae ; https://github.com/telepresenceio/telepresence/commit/36458b65a010d2b316af48cd90e193ba190785d9 ; https://github.com/telepresenceio/telepresence/commit/6871235b674a6e843908d09696354c4b0f91578c

Actions:

  • Fix: Upgrade Telepresence to 2.31.0 or later.
  • Workaround: Restrict port 8081 to trusted pods/namespaces and disable the Traffic Manager if it is not in active use.
  • Tradeoff: Restricting or disabling the Traffic Manager breaks local development intercept workflows.
KubernetesCVE-2026-102339CVSS 8.2 · HIGH

Summary: Telepresence before 2.31.0 does not verify that a caller owns the active session when attaching to the Traffic Manager Tunnel gRPC streaming endpoint. An attacker who obtains a valid active session ID can attach a routed tunnel to that session and gain its network routing capabilities.

Affected Features / Interoperability: The Traffic Manager Tunnel gRPC streaming endpoint and session-routing logic are affected. Downstream impact includes tunnel hijacking and access to traffic routed through the victim session.

Source: https://github.com/telepresenceio/telepresence/commit/1312482488b771742dbedd3015f9a81a27532de6 ; https://github.com/telepresenceio/telepresence/commit/36458b65a010d2b316af48cd90e193ba190785d9 ; https://github.com/telepresenceio/telepresence/pull/4217

Actions:

  • Fix: Upgrade Telepresence to 2.31.0 or later.
