Scoped Vulnerability Tracking

Cloud Security

The most urgent item is CVE-2026-113709 in Argo CD, a critical 9.9 vulnerability that can allow repository-controlled Helm plugin code to execute in `argocd-repo-server` when `--enable-helm` is used with Kustomize. It is not listed as CISA KEV-confirmed in the supplied data, but its high score, code-execution impact, and potential access to repository credentials warrant immediate review of Argo CD deployments, repository permissions, and Helm/Kustomize settings.

Formal Vulnerabilities

KubernetesCVE-2026-113709CVSS 9.9 · CRITICAL

Summary: Argo CD versions from 2.1.0 through 3.3.15, 3.4.10, 3.5.4, and 3.6.0-rc2 are affected when an operator enables `--enable-helm` for `kustomize build`. A repository can set `helmGlobals.configHome` to a controlled location, causing Helm to load and execute a downloader plugin when a Helm chart repository uses that protocol. The command runs as the `argocd-repo-server` user and may expose repository credentials.

Affected Features / Interoperability: Argo CD GitOps continuous delivery, specifically Helm support in Kustomize builds, Helm plugin loading, and the `argocd-repo-server` component. Repository credentials and other data accessible to the repo-server service account may be exposed; downstream deployments managed through the affected repository may also be compromised.

Source:

  • https://argo-cd.readthedocs.io/en/stable/user-guide/kustomize/#kustomizing-helm-charts
  • https://github.com/argoproj/argo-cd/commit/b6d5c23bce2f8a46c52975ba438a3b93d242d96c
  • https://github.com/argoproj/argo-cd/pull/6059
  • https://github.com/argoproj/argo-cd/releases/tag/v3.3.15
  • https://github.com/argoproj/argo-cd/releases/tag/v3.4.10

Actions:

  • Fix: Update to Argo CD 3.3.15 or 3.4.10, or to a later unaffected release; the supplied references also identify fixed versions 3.5.4 and 3.6.0-rc2.
  • Workaround: Disable `--enable-helm` for Kustomize builds and restrict repository-controlled values, particularly `helmGlobals.configHome`. Review and rotate repository credentials accessible to `argocd-repo-server`.
  • Tradeoff: Disabling Helm support in Kustomize reduces or removes that integration and may require teams to change their GitOps deployment workflows.
KubernetesCVE-2026-50516CVSS 9.4 · CRITICAL

Summary: Incorrect authorization in Microsoft Azure Kubernetes Service allows an authorized attacker to elevate privileges over the network. The flaw requires an attacker to have some existing authorization, but successful exploitation can result in privilege escalation.

Affected Features / Interoperability: Azure Kubernetes Service authorization and privilege controls. The supplied data does not specify the affected AKS components, permissions, or downstream integrations.

Source:

  • https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-50516

Actions:

  • Fix: No official patched version or release is specified in the supplied data; consult the Microsoft Security Response Center advisory for applicable AKS updates.
  • Workaround: Apply least-privilege RBAC and workload identity policies, review privileged access, and investigate suspicious privilege-escalation activity until the authoritative remediation guidance is available.
  • Tradeoff: Tightening RBAC may require additional administrative work and could disrupt workflows that rely on overly broad service-account permissions.
KubernetesCVE-2026-92982CVSS 8.5 · HIGH

Summary: A low-privileged Kubernetes user can inject malicious Jinja2 expressions through custom resource values processed by Ansible Operator Plugins. The expressions execute inside the operator pod, potentially resulting in arbitrary code execution, privilege escalation, and control of the operator’s service account, which may have cluster-wide permissions.

Affected Features / Interoperability: Ansible Operator Plugins, custom resource processing, and the operator pod’s Kubernetes service account. Cluster-scoped permissions, managed custom resources, and any resources accessible to the operator may be affected.

Source:

  • https://access.redhat.com/errata/RHSA-2026:87120
  • https://access.redhat.com/errata/RHSA-2026:87124
  • https://access.redhat.com/security/cve/CVE-2026-92982
  • https://bugzilla.redhat.com/show_bug.cgi?id=2522227

Actions:

  • Fix: Apply the applicable Red Hat security errata referenced above. The supplied data does not state the exact fixed package versions.
  • Workaround: Restrict creation and editing of affected custom resources to trusted administrators, reduce the operator service account’s RBAC permissions, and validate or reject suspicious template values.
  • Tradeoff: Restricting custom-resource access may reduce tenant self-service and require more centralized administration.
KubernetesCVE-2026-105311CVSS 7.7 · HIGH

Summary: A tenant permitted to create a StreamsHub Console custom resource can specify a victim namespace in `spec.kafkaClusters[].credentials.kafkaUser.namespace`. The operator uses cluster-wide Secret permissions to copy the referenced KafkaUser Secret—including SASL credentials or TLS private keys—into the attacker’s namespace. No same-namespace restriction or allowlist is present in the affected path.

Affected Features / Interoperability: StreamsHub Console operator reconciliation, KafkaUser Secret access, namespace-scoped credential handling, and any Kafka, SASL, or TLS integrations whose credentials are stored in those Secrets.

Source:

  • https://access.redhat.com/security/cve/CVE-2026-105311
  • https://bugzilla.redhat.com/bugzilla/show_bug.cgi?id=2510875

Actions:

  • Fix: No fixed version or official patch is identified in the supplied data; use the Red Hat CVE and bug records for remediation guidance.
  • Workaround: Prevent untrusted tenants from creating or modifying Console custom resources, restrict the operator’s Secret RBAC, and monitor for Console resources that reference KafkaUsers in other namespaces.
  • Tradeoff: Restricting the operator’s Secret permissions or Console creation can interfere with legitimate multi-namespace Kafka integrations.

DockerCVE-2026-114087CVSS 8.1 · HIGH

Summary: Trigger.dev self-hosted Docker Compose deployments before 4.5.6 that use the default secrets from `hosting/docker/.env.example` allow authentication bypass. A hardcoded `MAGIC_LINK_SECRET` lets unauthenticated attackers forge magic-link tokens for any email address; default credentials in runner containers may then provide access to Postgres, Redis, and ClickHouse data.

Affected Features / Interoperability: Trigger.dev authentication, magic-link token generation, self-hosted Docker Compose deployments, runner containers, and connected Postgres, Redis, and ClickHouse services.

Source:

  • https://github.com/triggerdotdev/trigger.dev/security/advisories/GHSA-pqxw-g93w-hj9x
