Scoped Vulnerability Tracking

Cloud Security

The most urgent formal issue is CVE-2026-113709 in Argo CD (CVSS 9.9): a malicious GitOps repository can trigger command execution in the repository server when Helm support is enabled for Kustomize builds. No supplied entry is confirmed as CISA KEV-exploited, so urgency is based on the critical CVSS score, network-exposed repository configuration, and potential credential theft and code execution. Other priorities include the Azure Kubernetes Service authorization flaw, three independently exploitable Traefik ingress authentication bypasses, and a Trigger.dev deployment flaw that permits unauthenticated account takeover and access to backing data stores.

Formal Vulnerabilities

Microsoft AzureCVE-2026-50516CVSS 9.4 · CRITICAL

Summary: Incorrect authorization in Microsoft Azure Kubernetes Service lets an authorized attacker elevate privileges over the network. The issue requires an attacker who already has some authorized access to the affected AKS environment; the supplied data does not provide a CISA KEV status or remediation due date.

Affected Features / Interoperability: Microsoft Azure Kubernetes Service authorization and privilege boundaries are affected. Successful exploitation could compromise cluster workloads or other resources available to the elevated identity; the raw data does not identify specific affected API versions, add-ons, or Kubernetes configurations.

Source: https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-50516

Actions:

  • Fix: Consult the Microsoft Security Response Center advisory for the applicable AKS mitigation or upgrade; no patched version is specified in the supplied data.
  • Workaround: Review AKS RBAC, role assignments, and workload identities for excessive privilege, and remove unnecessary authorization until Microsoft guidance can be applied.
  • Tradeoff: Restricting RBAC and workload identities can interrupt legitimate cross-resource or cross-namespace workflows.
KubernetesCVE-2026-113709CVSS 9.9 · CRITICAL

Summary: Argo CD versions 2.1.0 through 3.3.15, 3.4.10, 3.5.4, and 3.6.0-rc2 contain a Helm plugin-loading vulnerability when the operator enables `--enable-helm` for Kustomize builds. A repository-controlled `helmGlobals.configHome` can cause a downloader plugin to be loaded and executed inside `argocd-repo-server`, allowing malicious repository content to expose credentials and execute commands as that service account.

Affected Features / Interoperability: Argo CD's Kustomize/Helm integration, Helm configuration and data directories, and repository-server plugin execution are affected. Repository credentials and other secrets accessible to the repository-server service account may be exposed; the supplied description was truncated before identifying all possible downstream impact.

Source:

  • https://argo-cd.readthedocs.io/en/stable/user-guide/kustomize/#kustomizing-helm-charts
  • https://github.com/argoproj/argo-cd/commit/b6d5c23bce2f8a46c52975ba438a3b93d242d96c
  • https://github.com/argoproj/argo-cd/pull/6059
  • https://github.com/argoproj/argo-cd/releases/tag/v3.3.15
  • https://github.com/argoproj/argo-cd/releases/tag/v3.4.10

Actions:

  • Fix: Upgrade to Argo CD 3.3.15, 3.4.10, 3.5.4, or 3.6.0-rc2 as applicable to the deployed branch.
  • Workaround: Disable `--enable-helm` for Kustomize builds and prevent repositories from controlling `helmGlobals.configHome`.
  • Tradeoff: Disabling Helm support removes or limits Helm-backed Kustomize chart workflows and may require changes to affected deployment repositories.
