Scoped Vulnerability Tracking

Cloud Security

The most urgent formal issue is CVE-2026-113709 in Argo CD, a critical 9.9 vulnerability that can enable repository-controlled Helm plugin execution in `argocd-repo-server`, potentially exposing repository credentials and enabling further compromise. The Azure Kubernetes Service authorization flaw (CVE-2026-50516, CVSS 9.4) and the Traefik Ingress NGINX authentication-bypass issues are also critical priorities; no formal entry in this dataset is explicitly marked as CISA KEV-confirmed.

Formal Vulnerabilities

Microsoft AzureCVE-2026-50516CVSS 9.4 · CRITICAL

Summary: Incorrect authorization in Microsoft Azure Kubernetes Service allows an authorized attacker to elevate privileges over the network. The flaw requires an attacker to already possess some authorized access, but can be exploited over the network to increase privileges within AKS.

Affected Features / Interoperability: The affected component is Microsoft Azure Kubernetes Service authorization. The specific affected AKS control-plane or workload permissions, and any downstream cluster, workload, or secret-access implications, are not detailed in the supplied data.

Source:

  • https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-50516

Actions:

  • Fix: No patched release or version is specified in the supplied data; follow the Microsoft Security Response Center guidance for CVE-2026-50516.
  • Workaround: Restrict access to affected AKS management and workload interfaces to trusted principals, and review Azure RBAC and Kubernetes authorization changes for suspicious privilege escalation activity.
  • Tradeoff: Narrowing management-plane access may reduce administrative convenience and require more tightly controlled operational workflows.
KubernetesCVE-2026-113709CVSS 9.9 · CRITICAL

Summary: Argo CD versions 2.1.0 through 3.3.15, 3.4.10, 3.5.4, and 3.6.0-rc2 are affected when an operator has enabled `--enable-helm` for Kustomize builds. A repository-controlled `helmGlobals.configHome` can cause Helm to load and execute a downloader plugin inside `argocd-repo-server`; the command runs as the repo-server user and may read repository credentials.

Affected Features / Interoperability: The affected components are Argo CD’s Kustomize/Helm integration, Helm plugin loading, and the `argocd-repo-server` execution environment. Repository credentials and Argo CD GitOps deployment workflows may be exposed or compromised.

Source:

  • https://argo-cd.readthedocs.io/en/stable/user-guide/kustomize/#kustomizing-helm-charts
  • https://github.com/argoproj/argo-cd/commit/b6d5c23bce2f8a46c52975ba438a3b93d242d96c
  • https://github.com/argoproj/argo-cd/pull/6059
  • https://github.com/argoproj/argo-cd/releases/tag/v3.3.15
  • https://github.com/argoproj/argo-cd/releases/tag/v3.4.10

Actions:

  • Fix: Upgrade to the listed fixed releases: Argo CD 3.3.15, 3.4.10, 3.5.4, or 3.6.0-rc2, as applicable.
  • Workaround: Disable `--enable-helm` for Kustomize builds and review repository configuration for attacker-controlled `helmGlobals.configHome` values. Treat repository credentials and other secrets accessible to `argocd-repo-server` as potentially exposed and rotate them where appropriate.
  • Tradeoff: Disabling Helm support for Kustomize reduces GitOps deployment flexibility and may require changing release or chart-management workflows.
KubernetesCVE-2026-50516CVSS 9.4 · CRITICAL

Summary: Incorrect authorization in Microsoft Azure Kubernetes Service allows an authorized attacker to elevate privileges over the network. The vulnerability requires an authorized attacker but can be exploited remotely to obtain higher privileges.

Affected Features / Interoperability: The affected component is Microsoft Azure Kubernetes Service authorization. Specific affected AKS resources and downstream effects are not described in the supplied data.

Source:

  • https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-50516

Actions:

  • Fix: No patched release is specified in the supplied data; apply Microsoft’s guidance for CVE-2026-50516.
  • Workaround: Limit AKS access to trusted identities, review Azure RBAC assignments and Kubernetes RBAC bindings, and investigate unexpected privilege changes or service-account usage.
  • Tradeoff: More restrictive access controls can increase administrative overhead and may complicate legitimate cluster operations.
KubernetesCVE-2026-114636CVSS 8.7 · HIGH

Summary: Traefik v3.7.13 before v3.7.14 contains an access-control bypass in the Kubernetes Ingress NGINX provider.
