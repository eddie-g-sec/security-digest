Scoped Vulnerability Tracking

Database

The most urgent database-related issue is the Vitess debug endpoint cross‑site scripting flaw (CVE‑2026-104252, CVSS 9.8 CRITICAL), which allows a remote unauthenticated attacker to inject scripts that can read sensitive diagnostic data from exposed vttablet endpoints; immediate patching to Vitess 23.0.5 or 24.0.2 is advised.

Formal Vulnerabilities

MySQLCVE-2026-104252CVSS 9.8 · CRITICAL

Summary: Vitess versions before 23.0.5 and 24.0.2 reflect unsanitized user input from the `/twopcz` HTTP debug endpoint into HTML responses. An unauthenticated attacker can craft a request that executes JavaScript in the operator’s browser, allowing theft of same‑origin diagnostic data such as queries, transactions, and environment variables.

Affected Features / Interoperability: The `twopczHandler` in the Vitess tablet server’s debug endpoint is impacted; exposure of this endpoint can compromise internal diagnostics and potentially lead to further credential or data leakage.

Source:

  • https://github.com/vitessio/vitess/commit/3140c1846cd120db34f33b2083139b4ab638aed2
  • https://github.com/vitessio/vitess/commit/976e1e0d78f9d29d02e5e31b4aa7e180648f08af
  • https://github.com/vitessio/vitess/commit/c1ed96302e658190168c971afdac730cf70e43f7
  • https://github.com/vitessio/vitess/pull/20255
  • https://github.com/vitessio/vitess/pull/20273

Actions:

  • Fix: Upgrade to Vitess 23.0.5 or 24.0.2.
  • Workaround: Restrict network access to the `/twopcz` debug endpoint (e.g., firewall rules, VPN, or disable the debug endpoint if not required).
  • Tradeoff: Blocking the debug endpoint may hinder operational troubleshooting and performance monitoring for administrators who rely on it.
MySQLCVE-2026-110911CVSS 9.8 · CRITICAL

Summary: Wheels versions 1.1.8 through 4.1.1 improperly handle escaped single quotes in dynamic finder and query‑builder APIs, enabling SQL injection when application‑supplied data is reused as SQL. Attackers can bypass authentication, password‑reset, or token‑lookup protections and access or modify data without authorization.

Affected Features / Interoperability: The dynamic finder methods (e.g., `findOneByEmail`), query‑builder `where()` clauses, and key‑based lookup/validation functions are affected; any downstream functionality that relies on these APIs (user login, password reset, API token validation) could be compromised.

Source:

  • https://github.com/wheels-dev/wheels/security/advisories/GHSA-96rm-h22v-925x

Actions:

  • Fix: Upgrade to Wheels 4.1.2.
  • Workaround: Validate and sanitize all user‑supplied input before passing it to Wheels dynamic finder or query‑builder methods; employ prepared statements or ORM escaping layers.
  • Tradeoff: Input validation adds processing overhead and requires careful implementation to avoid breaking legitimate functionality that expects certain quote patterns.
MySQLCVE-2026-108806CVSS 7.3 · HIGH

Summary: The EmployeeRecruitmentSystem’s `mysql_query` call in `source/authprocessing.php` uses the `fpemail` parameter without sanitization, permitting remote SQL injection via the forgot‑password handler. The product lacks versioning and is unsupported, so no official patches exist.

Affected Features / Interoperability: The forgot‑password authentication flow is impacted; exploitation could lead to credential bypass, unauthorized access to recruitment data, or further database manipulation.

Source:

  • https://github.com/xiaotian2023/CVE/issues/2
  • https://vuldb.com/cve/CVE-2026-108806
  • https://vuldb.com/submit/963380
  • https://vuldb.com/vuln/416583
  • https://vuldb.com/vuln/416583/cti

Actions:

  • Fix: No patched version available; consider migrating to a supported alternative.
  • Workaround: Deploy a web‑application firewall (WAF) rule to block SQL‑like patterns in the `fpemail` parameter and restrict direct access to the authentication script to trusted networks.
  • Tradeoff: WAF rules may generate false positives, potentially blocking legitimate password‑reset requests if not finely tuned.
MySQLCVE-2026-102466UNSCORED

Summary: The Vert.x MySQL client pre‑allocates memory for column definitions based on an unverified server‑declared count. A malicious or compromised MySQL server (or MITM) can send an excessively large column count, triggering a massive heap allocation that crashes the client with an OutOfMemoryError, causing denial of service.

Affected Features / Interoperability: The `io.vertx:vertx-mysql-client` component is affected; any Vert.x application relying on this client for database connectivity could lose all database connections and associated services.

Source:

  • https://github.com/eclipse-vertx/vertx-sql-client/security/advisories/GHSA-9jxp-x3fr-ffqh
  • https://gitlab.eclipse.org/security/cve-assignment/-/work_items/342

Actions:

  • Fix: No specific patched version indicated in the source; monitor the Vert.x project for a release that adds validation.
  • Workaround: Enforce TLS‑encrypted connections to prevent MITM manipulation and restrict MySQL server access to trusted, vetted instances; consider using a proxy that validates result‑set metadata.
  • Tradeoff: Encryption adds computational overhead; proxy validation may introduce latency and requires additional infrastructure.
MySQLCVE-2026-103224UNSCORED

Summary: The Vert.x MySQL message decoder accumulates inbound packets without a size limit, allowing a malicious or compromised server to stream maximum‑sized packets and exhaust client memory, leading to an OutOfMemoryError before authentication completes.

Affected Features / Interoperability: Impacts the `io.vertx:vertx-mysql-client` component; any Vert.x‑based application using this client could suffer a total loss of database connectivity and dependent services.

Source:

  • https://github.com/eclipse-vertx/vertx-sql-client/security/advisories/GHSA-75hv-9xj3-3cr8
  • https://gitlab.eclipse.org/security/cve-assignment/-/work_items/353

Actions:

  • Fix: No specific patched version indicated; watch for a Vert.x release that adds cumulative size checks.
  • Workaround: Use TLS to mitigate MITM risk, limit MySQL server exposure to trusted hosts, and deploy client‑side connection timeouts and memory‑usage monitoring.
  • Tradeoff: TLS overhead and monitoring may affect performance; strict connection limits could disrupt legitimate high‑volume workloads.
PostgreSQLCVE-2017-12172CVSS 6.7 · MEDIUM

Summary: PostgreSQL versions prior to the listed patches allow a database superuser to replace the log file name with a symlink; when root starts the server, the privileged open/chmod/chown operations on the symlink enable the superuser to escalate to root privileges on the host OS.

Affected Features / Interoperability: The database startup script’s log‑file handling is affected; exploitation could lead to full host compromise, jeopardizing all services running on the server, including other databases, applications, and backup systems.

Source:

  • http://www.securityfocus.com/bid/101949
  • http://www.securitytracker.com/id/1039752
  • https://access.redhat.com/errata/RHSA-2017:3402
  • https://access.redhat.com/errata/RHSA-2017:3403
  • https://access.redhat.com/errata/RHSA-2017:3404

Actions:

  • Fix: Upgrade to PostgreSQL 10.1, 9.6.6, 9.5.10, 9.4.15, 9.3.20, or 9.2.24 (or newer).
  • Workaround: Run the PostgreSQL service under a dedicated non‑privileged account and ensure the log directory is not writable by the database superuser; restrict root‑initiated startups to trusted administrators.
  • Tradeoff: Changing the service account may require adjustments to file permissions and backup scripts; limiting root startups could affect automated provisioning tools that rely on root execution.
PostgreSQLCVE-2026-110861CVSS 3.7 · LOW

Summary: A race condition in the Better Auth PostgreSQL adapters allows concurrent requests to bypass rate‑limiting checks, enabling attackers to exceed configured limits on sign‑in, 2FA, OTP, and password‑reset endpoints.

Affected Features / Interoperability: The database‑backed rate‑limiting logic in `@better-auth/drizzle-adapter`, `better-auth`, and `@better-auth/kysely-adapter` is impacted; any application relying on these adapters for authentication throttling could experience credential‑stuffing or denial‑of‑service via excessive request volume.

Source:

  • https://github.com/better-auth/better-auth/security/advisories/GHSA-44jh-23m7-hpcf
  • https://www.vulncheck.com/advisories/better-auth-drizzle-adapter-1.6.17-before-1.7.7-rate-limit-bypass-via-race-condition

Actions:

  • Fix: Upgrade `@better-auth/drizzle-adapter` and `better-auth` to ≥ 1.7.7, and `@better-auth/kysely-adapter` to ≥ 1.7.0.
  • Workaround: Deploy an external API gateway or sidecar proxy that enforces rate limits at the network layer before requests reach the application.
  • Tradeoff: Adding an external rate‑limiting layer introduces latency and requires separate configuration and monitoring; misconfiguration could inadvertently block legitimate traffic.
PostgreSQLCVE-2026-102463UNSCORED

Summary: The Vert.x PostgreSQL client’s binary array decoder allocates a Java array based on an unchecked 32‑bit dimension count from the server. A malicious or compromised PostgreSQL server (or MITM) can send an excessively large dimension value, causing a multi‑gigabyte heap allocation and an OutOfMemoryError that crashes the client.

Affected Features / Interoperability: Impacts the `io.vertx:vertx-pg-client` component; any Vert.x application using this client could lose all PostgreSQL connectivity and dependent services.

Source:

  • https://github.com/eclipse-vertx/vertx-sql-client/security/advisories/GHSA-xqmh-8fhj-48fp
  • https://gitlab.eclipse.org/security/cve-assignment/-/work_items/345

Actions:

  • Fix: No specific patched version indicated; monitor for a Vert.x release that adds dimension validation.
  • Workaround: Enforce TLS to prevent MITM tampering, restrict PostgreSQL server access to trusted instances, and consider using a connection‑pooling proxy that validates array metadata.
  • Tradeoff: TLS overhead and proxy validation may increase latency and operational complexity.
PostgreSQLCVE-2026-103223UNSCORED

Summary: The Vert.x PostgreSQL message decoder reads the 4‑byte length field without upper‑bound validation, allowing a malicious or compromised server to send an arbitrarily large length value and cause unbounded memory accumulation, leading to an OutOfMemoryError before authentication.

Affected Features / Interoperability: Affects the `io.vertx:vertx-pg-client` component; any Vert.x‑based application relying on this client could suffer a total loss of PostgreSQL connectivity and related services.

Source:

  • https://github.com/eclipse-vertx/vertx-sql-client/security/advisories/GHSA-hm2j-xp3c-jff2
  • https://gitlab.eclipse.org/security/cve-assignment/-/work_items/354

Actions:

  • Fix: No specific patched version indicated; watch for a Vert.x release that adds length‑field validation.
  • Workaround: Use TLS to mitigate MITM risk, limit server access to trusted hosts, and implement client‑side connection timeouts and memory‑usage alerts.
  • Tradeoff: TLS encryption adds computational overhead; aggressive timeouts may drop legitimate long‑running queries, and monitoring requires additional tooling.

Cloud Security

The most urgent issue is the authorization bypass in Microsoft Azure Active Directory B2C (CVE-2026-83711), which carries a CVSS score of 10.0 and allows an unauthenticated attacker to elevate privileges over the network without any authentication, posing an immediate risk to identity‑dependent workloads in the healthcare cloud environment.

Formal Vulnerabilities

Microsoft AzureCVE-2026-83711CVSS 10.0 · CRITICAL

Summary: Authorization bypass through a user‑controlled key in Azure AD B2C lets an unauthenticated attacker elevate privileges by manipulating the key over the network; no authentication is required.

Affected Features / Interoperability: Azure AD B2C authorization logic; impacts any application relying on B2C for user authentication and could undermine IAM policies, conditional access, and federated trust.

Source: https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-83711

Actions:

  • Fix: Patch version not specified in the advisory.
  • Workaround: Restrict network access to Azure AD B2C endpoints, enforce strict conditional access policies, and monitor for anomalous privilege escalation events.
  • Tradeoff: Limiting network exposure may affect legitimate remote admin or partner integrations; monitoring adds operational overhead.
KubernetesCVE-2026-77459CVSS 9.9 · CRITICAL

Summary: Argo CD creates PostDelete resource hooks without applying AppProject destination and resource authorization checks, enabling a user with write access to an Application’s Git repository to inject a delete hook that creates forbidden resources with the controller’s cluster credentials.

Affected Features / Interoperability: Argo CD PostDelete hook processing; affects cluster‑scoped and namespaced resources managed by Argo CD, potentially allowing privilege escalation and unauthorized workload deployment.

Source: https://github.com/argoproj/argo-cd/commit/1149cdc6e932208c4402183cc3d7b7485239940c, https://github.com/argoproj/argo-cd/commit/4bc8085b0a6d2296b849539d3d09fc7be7a4a511, https://github.com/argoproj/argo-cd/commit/7f0a05834b05103d69d7c150e1ee36541b314696, https://github.com/argoproj/argo-cd/commit/d5dd7019ee65be8895133fe4df554e28074242c4, https://github.com/argoproj/argo-cd/releases/tag/v3.3.15

Actions:

  • Fix: Upgrade to Argo CD versions 3.3.15, 3.4.10, 3.5.4, or 3.6.0-rc2.
  • Workaround: Restrict who can write to Application Git repositories and enforce strict AppProject policies via RBAC or admission controllers.
  • Tradeoff: Limiting repository write access may impede CI/CD automation and require tighter change‑control processes.
KubernetesCVE-2026-77524CVSS 9.9 · CRITICAL

Summary: In KEDA ≤2.20.2, a namespace admin who can create TriggerAuthentication and ScaledObject resources can point hashicorpVault.address at a tenant‑controlled endpoint; KEDA then sends the operator pod’s projected ServiceAccount token to that endpoint, allowing the attacker to inherit the operator’s cluster‑wide permissions.

Affected Features / Interoperability: KEDA Vault authentication integration; impacts any autoscaling workloads that rely on KEDA‑Vault integration, potentially leading to secret exposure and unauthorized cluster actions.

Source: https://github.com/kedacore/keda/commit/1e21cc798dedd079e696cdb45388eddc5e18365d, https://github.com/kedacore/keda/releases/tag/v2.21.0, https://github.com/kedacore/keda/security/advisories/GHSA-637c-6jxx-4rwm

Actions:

  • Fix: Upgrade to KEDA version 2.21.0.
  • Workaround: Prevent namespace admins from creating TriggerAuthentication/ScaledObject resources or enforce strict validation of the Vault address field via admission webhooks.
  • Tradeoff: Restricts legitimate use of KEDA’s Vault‑based autoscaling and may require alternative secret‑injection methods.
KubernetesCVE-2026-92982CVSS 8.5 · HIGH

Summary: A low‑privileged Kubernetes user can inject arbitrary Jinja2 expressions into a custom resource spec that is processed by an Ansible Operator without sanitization, leading to remote code execution and privilege escalation via the operator’s service account.

Affected Features / Interoperability: Ansible Operator Plugins; affects any operator using Ansible for Kubernetes resource management, potentially enabling full cluster compromise.

Source: https://access.redhat.com/security/cve/CVE-2026-92982, https://bugzilla.redhat.com/show_bug.cgi?id=2522227

Actions:

  • Fix: Patch version not specified in the advisory.

  • Tradeoff: May block legitimate templating use‑cases and increase admission‑controller overhead.
