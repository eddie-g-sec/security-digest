Scoped Vulnerability Tracking

Cloud Security

The most urgent item in today’s cloud security formal vulnerability data is Dockhand CVE-2026-134452 (CVSS 8.8 [HIGH]), an authenticated remote command execution via unsanitized stack secret environment variables (notably `PATH`) during Docker Compose stack deploys in Dockhand before 1.0.57. Although no CISA KEV confirmation was present in the supplied formal data, this is the highest-severity confirmed formal vulnerability in scope, so it outranks the lower-severity Heym issue. The Heym flaw (CVE-2026-134360, CVSS 6.5 [MEDIUM]) remains notable but less urgent.

Formal Vulnerabilities

Kubernetes — CVE-2026-134360 (CVSS 6.5 [MEDIUM])

Summary: Heym before 0.0.148 passes Playwright navigate-step URLs to `page.goto()` without validating the scheme and runs step-based scripts inside the backend container. A signed-in user who can run workflows can navigate to `file://` URLs and use `getText` to read known-path files such as the Kubernetes ServiceAccount token or Docker secrets.

Affected Features / Interoperability: Impacts Playwright navigate-step handling, workflow execution, and the backend container. Could allow local file read of known paths; raw data did not detail broader cloud integration effects.

Source: https://github.com/heymrun/heym/security/advisories/GHSA-hmfh-wpg2-vff4 ; https://www.vulncheck.com/advisories/heym-before-0.0.148-local-file-read-via-playwright-navigate-step

Actions:

  • Fix: Upgrade to a release addressing the issue (affected versions before 0.0.148).
  • Workaround: Restrict which signed-in users can run workflows and validate navigate-step URLs before execution.
  • Tradeoff: Restricting workflow execution may affect legitimate automation.

Docker — CVE-2026-134452 (CVSS 8.8 [HIGH])

Summary: Dockhand before 1.0.57 merges stack secret environment variables into the environment used to spawn Docker Compose during stack deploys without filtering reserved keys such as `PATH`. An authenticated attacker with `stacks:edit` permission can set `PATH` to a directory containing a malicious binary and trigger a deploy, executing arbitrary commands as the Dockhand server process user.

Affected Features / Interoperability: Impacts stack secret environment variables, stack deploy behavior, and spawned Docker Compose process. Downstream impact includes arbitrary command execution as the Dockhand server process user; raw data did not specify broader cloud IAM or Kubernetes effects.

Source: https://github.com/Finsys/dockhand/security/advisories/GHSA-8fh8-h5v2-wmj4 ; https://www.vulncheck.com/advisories/dockhand-before-1.0.57-rce-via-path-poisoning-in-stack-deploy

Actions:

  • Fix: Upgrade to a release addressing the issue (affected versions before 1.0.57).
  • Workaround: Restrict `stacks:edit` permission and audit/rotate stack secret environment variables; avoid reserved keys such as `PATH` in stack secrets.
  • Tradeoff: Restricting `stacks:edit` may affect developer or automation workflows; removing/rotating `PATH` may degrade container tooling or deployment behavior.

Docker — CVE-2026-134360 (CVSS 6.5 [MEDIUM])

Summary: Heym before 0.0.148 passes Playwright navigate-step URLs to `page.goto()` without validating the scheme and runs step-based scripts inside the backend container. A signed-in user who can run workflows can navigate to `file://` URLs and use `getText` to read known-path files such as the Kubernetes ServiceAccount token or Docker secrets.

Affected Features / Interoperability: Impacts Playwright navigate-step handling, workflow execution, and backend container. Could allow local file read of known paths; raw data did not detail broader cloud integration effects.

Source: https://github.com/heymrun/heym/security/advisories/GHSA-hmfh-wpg2-vff4 ; https://www.vulncheck.com/advisories/heym-before-0.0.148-local-file-read-via-playwright-navigate-step
