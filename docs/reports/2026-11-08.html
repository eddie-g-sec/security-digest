Scoped Vulnerability Tracking

Cloud Security

The most urgent item in this cloud security scope is CVE-2025-59358 in Kubernetes, a high-severity (CVSS 7.5) vulnerability in Chaos Mesh's Chaos Controller Manager. This vulnerability exposes an unauthenticated GraphQL debugging server to the entire Kubernetes cluster, allowing any network-attacker to kill arbitrary processes in pods and trigger a cluster-wide denial of service. Because there are no CISA KEV-confirmed entries in the current dataset, this high-severity, unauthenticated remote attack vector represents the most critical immediate threat to cloud container orchestration environments.

Formal Vulnerabilities

KubernetesCVE-2025-59358CVSS 7.5 · HIGH

Summary: The Chaos Controller Manager in Chaos Mesh exposes a GraphQL debugging server without authentication to the entire Kubernetes cluster, which provides an API to kill arbitrary processes in any Kubernetes pod, leading to cluster-wide denial of service. This vulnerability is network-reachable and requires no authentication, making it easily exploitable by any actor with network access to the cluster.

Affected Features / Interoperability: Impacts the Chaos Controller Manager component of Chaos Mesh. Downstream functionality related to pod process management, chaos experimentation orchestration, and overall cluster stability is directly impacted, potentially leading to complete denial of service across all pods in the cluster.

Source:

  • https://github.com/chaos-mesh/chaos-mesh/pull/4702
  • https://jfrog.com/blog/chaotic-deputy-critical-vulnerabilities-in-chaos-mesh-lead-to-kubernetes-cluster-takeover

Actions:

  • Fix: Upgrade Chaos Mesh to the patched version as indicated in the official pull request/advisory (refer to GitHub PR 4702).
  • Workaround: Restrict network access to the Chaos Mesh controller manager using Kubernetes NetworkPolicies, ensuring the debugging port is not accessible from unauthorized pods or networks.
  • Tradeoff: Restricting network access may limit the ability of cluster administrators to perform legitimate debugging or monitoring tasks within the cluster.
DockerCVE-2025-55473CVSS 6.1 · MEDIUM

Summary: Asian Arts Talents Foundation (AATF) Website v5.1.x and Docker version 2024.12.8.1 are vulnerable to Cross-Site Scripting (XSS) in the `/ip.php` endpoint, which processes and displays the `X-Forwarded-For` HTTP header without proper sanitization or output encoding. This allows an attacker to inject malicious JavaScript code that will execute in visitor browsers. The vulnerability is network-reachable and requires no authentication to exploit.

Affected Features / Interoperability: Impacts the `/ip.php` endpoint of the AATF website running on Docker version 2024.12.8.1. Downstream functionality such as client-side scripting, user session management, and page integrity can be compromised, potentially allowing session hijacking or redirection to malicious sites for visitors.

Source:

  • https://cyber-ducky.com/xss-found-in-asian-arts-talent-foundation-2/
  • https://github.com/AATF/aatf.us
  • https://hub.docker.com/r/aatf/aatf.us

Actions:

  • Fix: Update the AATF website application to a patched version or upgrade the Docker image to one that includes proper input sanitization and output encoding for the `X-Forwarded-For` header.
  • Workaround: Deploy a Web Application Firewall (WAF) rule to inspect and filter the `X-Forwarded-For` header for malicious scripts before reaching the application.
  • Tradeoff: WAF filtering of HTTP headers might occasionally block legitimate requests containing unusual but valid characters, potentially causing minor disruption to normal users.
DockerCVE-2026-123508CVSS 3.1 · LOW

Summary: Vikunja before version 2.7.1 contains a supply chain vulnerability in its mage release targets that fetch the xgo module and Docker image by mutable latest references. Attackers who compromise the upstream xgo module, image, or registry can inject malicious code into subsequently built release binaries shipped under a valid signature. Exploitation requires the ability to compromise upstream build dependencies or the registry.

Affected Features / Interoperability: Impacts the build pipeline and release integrity of the Vikunja application. Downstream functionality includes the trustworthiness of the compiled application binary, which could lead to arbitrary code execution if a compromised build is deployed to production.

Source:

  • https://github.com/go-vikunja/vikunja/security/advisories/GHSA-h8wj-3gwg-jjjg
  • https://www.vulncheck.com/advisories/vikunja-before-2.7.1-supply-chain-risk-via-unpinned-xgo-release-toolchain

Actions:

  • Fix: Upgrade Vikunja to version 2.7.1 or later, which resolves the supply chain risk by pinning the xgo release toolchain to immutable references.
  • Workaround: Verify the cryptographic signatures of release binaries and ensure that build processes do not pull from mutable tags or unverified registries.
  • Tradeoff: Enforcing strict signature verification and pinning dependencies adds complexity and overhead to the CI/CD pipeline, potentially slowing down build times and release cycles.
