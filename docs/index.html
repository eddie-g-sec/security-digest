Scoped Vulnerability Tracking

Cloud Security

No CISA KEV-confirmed entries appear in the formal vulnerability data. The single most urgent item is Docker CVE-2022-38362 (CVSS 8.8 HIGH), an authenticated remote code execution flaw in an Apache Airflow Docker Provider example DAG prior to 3.0.0; it is the highest-scored formal issue and should be prioritized for removal or upgrade. Google Cloud Platform has three unscored but potentially high-impact issues, including an unauthenticated Vertex AI Assistant API missing-authorization flaw, but the formal data provides no CVSS score or KEV confirmation for those entries.

Formal Vulnerabilities

Google Cloud Platform — CVE-2026-106169 (CVSS UNSCORED, severity not provided)

Summary: A deserialization of untrusted data vulnerability in the eventbus execution in Google Cloud Application Integration versions prior to 2026-09-22 allows an authenticated attacker to achieve remote code execution using a crafted serialized Java object. Google patched this on 22 September 2026 and states no customer action is needed.

Affected Features / Interoperability: The impacted component is the eventbus execution in Google Cloud Application Integration. The raw data does not specify downstream integrations or interoperability effects.

Source: https://docs.cloud.google.com/support/bulletins#gcp-2026-083

Actions:

  • Fix: Google patched the issue on 2026-09-22; no customer action is needed per the advisory.
  • Workaround: None specified; Google states no customer action is needed.
  • Tradeoff: No significant tradeoff.

Google Cloud Platform — CVE-2026-110739 (CVSS UNSCORED, severity not provided)

Summary: An incomplete list of disallowed inputs in the namespace onboarding API in Google Cloud GKE Fleet versions prior to 2026-09-25 allows an authenticated attacker to escalate privileges to project owner using a privileged system namespace onboarding request. Google patched this on 25 September 2026 and states no customer action is needed.

Affected Features / Interoperability: The impacted component is the GKE Fleet namespace onboarding API and privileged system namespace onboarding. The raw data does not specify downstream IAM, networking, or orchestration effects beyond project-owner privilege escalation.

Source: https://docs.cloud.google.com/kubernetes-engine/docs/release-notes#September_25_2026

Actions:

  • Fix: Google patched the issue on 2026-09-25; no customer action is needed per the advisory.
  • Workaround: None specified; Google states no customer action is needed.
  • Tradeoff: No significant tradeoff.

Google Cloud Platform — CVE-2026-85258 (CVSS UNSCORED, severity not provided)

Summary: A missing authorization vulnerability in the private console API in Google Cloud Vertex AI Assistant versions prior to 2026-04-13 allows an unauthenticated remote attacker to list, read, create, and send messages in other users' chat sessions using crafted API requests. Google patched this on 13 April 2026 and states no customer action is needed.

Affected Features / Interoperability: The impacted component is the Vertex AI Assistant private console API and chat-session messaging. The raw data does not specify downstream integrations or interoperability effects.

Source: https://docs.cloud.google.com/vertex-ai/docs/release-notes#April_13_2026

Actions:

  • Fix: Google patched the issue on 2026-04-13; no customer action is needed per the advisory.
  • Workaround: None specified; Google states no customer action is needed.
  • Tradeoff: No significant tradeoff.
KubernetesCVE-2026-10533CVSS 5.0 · MEDIUM

Summary: A flaw in OpenShift Container Platform causes completed pods with `restartPolicy: Never` not to count toward ResourceQuota pod limits, and Kubernetes events are not quota-scoped. A non-privileged user who can create pods in a namespace can exploit this to generate a large volume of events that accumulate in etcd, causing API server performance degradation across the cluster.

Affected Features / Interoperability: The impacted features are ResourceQuota pod limits, Kubernetes events, etcd, and API server performance. Downstream cluster-wide API performance can degrade.

Source: https://access.redhat.com/security/cve/CVE-2026-10533, https://bugzilla.redhat.com/show_bug.cgi?id=2483727

Actions:

  • Fix: No patched version is provided in the supplied data.
  • Workaround: No official workaround is provided; interim risk reduction is to restrict pod creation in affected namespaces and monitor etcd/API-server load.
  • Tradeoff: Restricting pod creation can break legitimate workloads; monitoring has no significant tradeoff.
DockerCVE-2022-38362CVSS 8.8 · HIGH

Summary: Apache Airflow Docker’s Provider prior to 3.0.0 shipped with an example DAG that was vulnerable to authenticated remote code execution on the Airflow worker host. An authenticated attacker could exploit the example DAG to run code on the worker.

Affected Features / Interoperability: The impacted component is the Apache Airflow Docker Provider example DAG and the Airflow worker host. The raw data does not specify downstream integrations.

Source: http://www.openwall.com/lists/oss-security/2022/08/16/1, https://lists.apache.org/thread/614p38nf4gbk8xhvnskj9b1sqo2dknkb

Actions:

  • Fix: Upgrade the Apache Airflow Docker Provider to 3.0.0 or later and remove the vulnerable example DAG.
  • Workaround: Remove or disable the vulnerable example DAG and restrict authenticated access to Airflow.
  • Tradeoff: Removing example DAGs can break demos or examples; restricting access can impede legitimate users.
DockerCVE-2026-77230CVSS 8.1 · HIGH

Summary: Camunda 8.8.0 before 8.8.47, 8.9.0 before 8.9.29, 8.10.0 before 8.10.10, and 8.11.0-alpha1 contain an insecure deserialization vulnerability in the persistent web session feature. Session attributes are stored as Java-serialized data in secondary storage and deserialized without an ObjectInputFilter; attackers with write access to the web session index, such as an unauthenticated Elasticsearch cluster deployed via Camunda docker-compose files, can plant a crafted serialized object and trigger deserialization with a matching session cookie.

Affected Features / Interoperability: The impacted features are Camunda persistent web sessions, secondary storage, the web session index, Elasticsearch deployments, and session cookies. Downstream session handling and integrations relying on persistent sessions may be affected.

Source: https://github.com/camunda/camunda/commit/5870c91d4ec8c2dae96db60f3261daed2273baf2, https://github.com/camunda/camunda/commit/82b490cd41a685118b63a378d8963334711b7d8d, https://github.com/camunda/camunda/commit/aaf0498ec37dc9b43dbbab2616f3bf5303f911ce

Actions:

  • Fix: Upgrade Camunda to 8.8.47, 8.9.29, 8.10.10, or 8.11.0-alpha1 or later as applicable.
  • Workaround: Restrict write access to the web session index and Elasticsearch, require authentication, and network-isolate the session store.
  • Tradeoff: Restricting session-store access can break session persistence or integrations.

Docker — CVE-2026-126139 (CVSS UNSCORED, severity not provided)

Summary: Docker Sandboxes re-resolves saved mount paths when replacing a sandbox container during kit changes or restarting a sandbox. An attacker able to replace a source ancestor in a shared writable workspace with a symlink can redirect another sandbox’s mount to a different host directory, exposing its contents and permitting modification through read-write mounts. The destination must remain accessible to the daemon and allowed by policy where enforced.

Affected Features / Interoperability: The impacted features are Docker Sandboxes saved-mount replay, kit replacement, sandbox restart, shared writable workspaces, and read-write mounts. Downstream sandbox isolation and mount behavior can be affected.

Source: https://docs.docker.com/ai/sandboxes/, https://docs.docker.com/ai/sandboxes/security/isolation/#hypervisor-isolation

Actions:

  • Fix: No patched version is provided in the supplied data.
  • Workaround: Restrict write access to shared writable workspaces, prevent symlink replacement of source ancestors, and enforce mount policy.
  • Tradeoff: Restricting shared workspace writes can break kit-change and sandbox-restart workflows.
