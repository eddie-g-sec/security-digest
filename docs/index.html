Scoped Vulnerability Tracking

Cloud Security

This batch contains no CISA KEV-confirmed entries, so prioritization is driven by CVSS severity and exposure context. The single most urgent item is CVE-2026-134452 in Dockhand (Docker), CVSS 8.8 HIGH, which lets an authenticated attacker with `stacks:edit` permission poison `PATH` during stack deploys and achieve remote code execution as the Dockhand server process user. Other notable issues include CVE-2026-129509 in the Apache Airflow Microsoft Azure provider (TLS certificate verification disabled by default for S3 traffic), CVE-2026-126054 in Google Cloud Dataform/BigQuery Studio/Colab Enterprise (path traversal, already vendor-patched with no customer action required), and several Kubernetes and Docker supply-chain or access-control flaws including unauthenticated MCP tool invocation and CI/CD token leakage in build caches.

Formal Vulnerabilities

Microsoft AzureCVE-2026-129509CVSS 7.5 · HIGH

Summary: In the Apache Airflow Microsoft Azure provider versions 10.2.0 through 15.3.0, the `S3ToAzureBlobStorageOperator` disables TLS certificate verification for its Amazon S3 connection by default (`s3_verify=False`), overriding the AWS connection's own verification settings. An attacker positioned on the network between an Airflow worker and S3 can intercept traffic, read signed requests, and alter object keys and copied file contents. Exploitation requires a DAG that uses the operator without setting `s3_verify`; no additional authentication requirement is described beyond network positioning.

Affected Features / Interoperability: The `S3ToAzureBlobStorageOperator` in the Apache Airflow Microsoft Azure provider is impacted. DAGs copying objects between S3 and Azure Blob Storage could transfer intercepted or altered data; no specific IAM, networking, or orchestration integrations are detailed in the source data.

Source: https://github.com/apache/airflow/pull/76222, https://lists.apache.org/thread/z6o61d0h81o1f9bgdrn4d9jl24o7shmh, http://www.openwall.com/lists/oss-security/2026/11/17/30

Actions:

  • Fix: Upgrade the Apache Airflow Microsoft Azure provider to a patched release (exact version not stated in the data).
  • Workaround: Explicitly set `s3_verify=True` (or the appropriate verification value) in every DAG using `S3ToAzureBlobStorageOperator`.
  • Tradeoff: Enabling certificate verification may break connections to S3 endpoints using self-signed or privately trusted certificates unless the CA bundle is also configured.
Google Cloud PlatformCVE-2026-126054UNSCORED

Summary: A path traversal vulnerability in workspace directory handling and Git integration in Google Cloud Dataform, BigQuery Studio, and Colab Enterprise allows an authenticated remote attacker to read private files and create arbitrary files across tenant repositories using crafted workspace operations and Git integration requests. Google states the issue was patched on 10 October 2026 and no customer action is needed.

Affected Features / Interoperability: Workspace directory handling and Git integration in Dataform, BigQuery Studio, and Colab Enterprise on GCP. Potential impact on tenant repository isolation and downstream processes consuming those repositories; specific IAM or integration details are not provided in the source data.

Source: https://docs.cloud.google.com/bigquery/docs/release-notes#November_19_2026, https://docs.cloud.google.com/dataform/docs/release-notes#November_19_2026, https://docs.cloud.google.com/support/bulletins/#gcp-2026-084

Actions:

  • Fix: Already patched by Google on 10 October 2026; no customer action required per the advisory.
  • Workaround: Not applicable (vendor-patched).
  • Tradeoff: No significant tradeoff.
KubernetesCVE-2026-134360CVSS 6.5 · MEDIUM

Summary: Heym before 0.0.148 passes Playwright navigate-step URLs to `page.goto()` without validating the scheme and runs step-based scripts inside the backend container. A signed-in user who can run workflows can navigate to `file://` URLs and use `getText` to read known-path files such as the Kubernetes ServiceAccount token or Docker secrets.

Affected Features / Interoperability: Heym workflow navigation steps and backend container script execution. Reading ServiceAccount tokens or Docker secrets could compromise cluster or container registry access; specific downstream integrations are not detailed in the source data.

Source: https://github.com/heymrun/heym/security/advisories/GHSA-hmfh-wpg2-vff4, https://www.vulncheck.com/advisories/heym-before-0.0.148-local-file-read-via-playwright-navigate-step

Actions:

  • Fix: Upgrade Heym to 0.0.148 or later.
  • Workaround: Restrict workflow execution to trusted users and avoid running untrusted workflows; no vendor-specified workaround is given in the data.
  • Tradeoff: Limiting workflow users reduces operational flexibility and may block legitimate automation.
KubernetesCVE-2026-130007UNSCORED

Summary: k8s-mcp-server before 1.1.0 defaults `SERVER_MODE` to SSE, with the listener on 0.0.0.0:8080, but creates the SSE server without an authentication option or context function. The `GET /sse` handler creates a sessionId that is only a correlation value, and the `POST /message` handler accepts a loadable sessionId without authorization or Origin checks before dispatching tools/call. Consequently, any client able to reach the port can enumerate and invoke registered Kubernetes tools without credentials.

Affected Features / Interoperability: The SSE endpoint of k8s-mcp-server and its Kubernetes tool dispatching. Unauthenticated tool invocation could affect cluster management operations integrated via MCP; specific downstream functionality is not detailed in the source data.

Source: https://github.com/reza-gholizade/k8s-mcp-server/commit/817d81005369837e0c034962785851ca4dec9a76, https://github.com/reza-gholizade/k8s-mcp-server/issues/131, https://github.com/reza-gholizade/k8s-mcp-server/pull/134

Actions:

  • Fix: Upgrade k8s-mcp-server to 1.1.0 or later.
  • Workaround: Block or restrict network access to port 8080 and bind the listener to localhost instead of 0.0.0.0.
  • Tradeoff: Binding to localhost or firewalling the port may break remote MCP clients that expect to reach the server over the network.
DockerCVE-2026-134452CVSS 8.8 · HIGH

Summary: Dockhand before 1.0.57 merges stack secret environment variables into the environment used to spawn `docker compose` during stack deploys without filtering reserved keys such as `PATH`. An authenticated attacker with `stacks:edit` permission can set `PATH` to a directory containing a malicious binary and trigger a deploy, executing arbitrary commands as the Dockhand server process user.

Affected Features / Interoperability: Dockhand stack deployment and secret environment variable handling. Arbitrary command execution as the Dockhand server user could compromise the host running Dockhand and any container orchestration it controls; specific downstream features are not detailed in the source data.

Source: https://github.com/Finsys/dockhand/security/advisories/GHSA-8fh8-h5v2-wmj4, https://www.vulncheck.com/advisories/dockhand-before-1.0.57-rce-via-path-poisoning-in-stack-deploy

Actions:

  • Fix: Upgrade Dockhand to 1.0.57 or later.
  • Workaround: Revoke or restrict `stacks:edit` permissions for untrusted users and review stack secret environment variables for reserved keys like `PATH`.
  • Tradeoff: Restricting `stacks:edit` may block legitimate users from updating stack configurations and secrets.
DockerCVE-2026-120676CVSS 7.2 · HIGH

Summary: The Forminator Forms WordPress plugin (all versions up to and including 1.58.4) is vulnerable to stored cross-site scripting via the file upload field's `element_id` parameter due to insufficient input sanitization and output escaping. Unauthenticated attackers can inject arbitrary web scripts that execute whenever a user accesses an injected page. This is an incomplete fix for CVE-2024-1794 and requires the File Upload field to be left at its default state.

Affected Features / Interoperability: Forminator Forms file upload functionality in WordPress. Compromised pages could affect any users viewing them, including administrators; no cloud-specific interoperability is described in the source data.

Source: https://plugins.trac.wordpress.org/browser/forminator/tags/1.58.4/library/abstracts/abstract-class-field.php#L2420, https://plugins.trac.wordpress.org/browser/forminator/tags/1.58.4/library/fields/upload.php#L399, https://plugins.trac.wordpress.org/browser/forminator/tags/1.58.4/library/fields/upload.php#L403

Actions:

  • Fix: No patched version is stated in the data.
  • Workaround: Disable or remove the File Upload field in Forminator forms, or restrict access to affected WordPress pages, until a patch is available.
  • Tradeoff: Disabling file uploads breaks form functionality that depends on user-submitted files.

DockerCVE-2026-133630UNSCORED

Summary: The flowintel Docker build workflow used the GitHub Actions `checkout` action with default credential persistence, causing the job authentication token to be written into the repository's Git configuration file. This file became part of the Docker build context and could be retained in exported build cache layers, even though Git metadata was stripped from the final runtime image. An attacker with access to the CI/CD build cache or build environment could extract the persisted token and use it to gain unauthorized access to the private source repository.

Affected Features / Interoperability: flowintel Docker build workflow and CI/CD build cache. Exposure of the GitHub token could compromise the private source repository and any integrated build or deployment pipelines; specific downstream functionality is not detailed in the source data.

Source: https://github.com/flowintel/flowintel/commit/6b26b3f8cf9fab13244d1496443f822114ce4d05

Actions:

  • Fix: No patched version is stated in the data; the referenced commit addresses the issue.
  • Workaround: Remove persisted credentials from Git configuration and build context, rotate exposed tokens, and disable default credential persistence in GitHub Actions checkout steps.
  • Tradeoff: Rotating tokens may temporarily break automated CI/CD pipelines until secrets are updated.
