Scoped Vulnerability Tracking

Cloud Security

The most urgent issue is a critical privilege escalation in Kyverno (CVE‑2026‑122310, CVSS 9.9) that lets a namespace‑scoped user who can create a Policy hide path traversal segments and gain cluster‑admin rights, effectively compromising the entire Kubernetes cluster.

Formal Vulnerabilities

AWSCVE-2026-121686UNSCORED

Summary: An unauthenticated remote code execution vulnerability in FrodoBots EarthRover Mini+ firmware allows attackers to execute arbitrary shell commands via AWS IoT MQTT messages, leveraging shared IoT credentials to compromise the entire fleet.

Affected Features / Interoperability: The vulnerable firmware method in EarthRover Mini+ (versions 6.2.4_6.2.5_0.614.0) impacts AWS IoT messaging and any downstream services that rely on the device, potentially affecting fleet management, data collection, and integration with cloud analytics.

Source:

  • https://github.com/frodobots-org
  • https://kb.cert.org/vuls/id/188754
  • https://www.frodobots.ai/

Actions:

  • Fix: Upgrade to the latest firmware version beyond 0.614.0 (specific patched version not disclosed).
  • Workaround: Disable MQTT communication for the device or enforce per‑device IoT credentials and network segmentation.
  • Tradeoff: Disabling MQTT may break real‑time telemetry; per‑device credentials increase management overhead.
KubernetesCVE-2026-122310CVSS 9.9 · CRITICAL

Summary: Kyverno versions 1.19.1 to before 1.19.2 incorrectly validate a Policy's context.apiCall urlPath, allowing a namespace‑scoped user who can create a Policy to hide ../ path traversal segments behind URL fragments or query parameters and reach cluster‑scoped endpoints, achieving cluster‑admin privileges.

Affected Features / Interoperability: The Kyverno policy validation logic and its ServiceAccount are affected, potentially compromising cluster‑wide resources, RBAC, and any Kubernetes API server interactions that rely on policy
