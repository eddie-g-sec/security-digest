Scoped Vulnerability Tracking

Cloud Security

Executive summary: No CISA KEV-confirmed entries were found in today's digest. The single most urgent item is CVE-2026-120306 (Beta9, CVSS 9.9, CRITICAL), a privilege escalation vulnerability in the Beta9 build worker that allows container escape and root-level access on the host. This affects both Kubernetes and Docker environments using Beta9 for tenant image builds.

Formal Vulnerabilities

AWSCVE-2026-115812CVSS 9.8 · CRITICAL

Summary: Relative path traversal during model archive extraction in AWS Multi Model Server 1.1.11 and earlier allows remote actors to execute arbitrary code via a crafted model archive. Multi Model Server is end of life with no fixed version available; users should discontinue use and migrate to a supported model serving solution.

Affected Features / Interoperability: Model archive extraction and model serving pipeline components. Downstream impacts include broken ML workload serving and potential exposure of sensitive model artifacts.

Source: https://aws.amazon.com/security/security-bulletins/2026-148-aws/

Actions:

  • Fix: No fixed version available; Multi Model Server is end of life
  • Workaround: Discontinue use of Multi Model Server and migrate to a supported model serving solution
  • Tradeoff: Migration effort required; no significant tradeoff from workaround itself
AWSCVE-2026-115813CVSS 5.8 · MEDIUM

Affected Features / Interoperability: Model download path and internal network reachability. Downstream impacts include potential exposure of internal services behind network segmentation.

Source: https://aws.amazon.com/security/security-bulletins/2026-148-aws/

Microsoft AzureCVE-2026-105769CVSS 9.3 · CRITICAL

Summary: kaniko before 1.25.20 can send a Microsoft Entra ID (Azure AD) access token for Azure Resource Manager to an attacker-controlled registry host. The credential helper uses an unanchored regex that accepts any hostname containing .azurecr.io, .azurecr.cn, .azurecr.de, or .azurecr.us.

Affected Features / Interoperability: Azure Container Registry credential helper and kaniko build process. Downstream impacts include broken container build isolation and potential credential leakage to attacker-controlled registries.

Source: https://github.com/chainguard-forks/kaniko/pull/495, https://github.com/chainguard-forks/kaniko/releases/tag/v1.25.20, https://github.com/chainguard-forks/kaniko/security/advisories/GHSA-5q7h-w9jf-cx97

  • Workaround: Restrict network access to Azure Container Registry hosts; avoid using the affected credential helper
  • Tradeoff: May require infrastructure changes to restrict registry access
KubernetesCVE-2026-120306CVSS 9.9 · CRITICAL

Summary: Beta9 turns each shell command in a tenant image definition into a Dockerfile RUN line executed with Buildah on the build worker. The worker sets BUILDAH_ISOLATION=chroot without passing --isolation, keeping PID, network, IPC, and user namespaces while running as uid 0 with CAP_DAC_OVERRIDE. PID 1 in procfs is the worker entrypoint, making /proc/1/root writable, containing runc, buildah, and runsc binaries.

Affected Features / Interoperability: Tenant image building, Buildah isolation, worker container filesystem. Downstream impacts include complete container escape, host root compromise, and cluster-wide impact.

Source: https://github.com/beam-cloud/beta9, https://github.com/beam-cloud/beta9/commit/a28bf12cf0007c792a25d8ed282b4e8bf6f30393, https://github.com/beam-cloud/beta9/pull/1897

Actions:

  • Fix: Upgrade Beta9 to a patched version (specific version not specified in data)
  • Workaround: Disable tenant image building or use alternative build tools
  • Tradeoff: Disabling tenant builds may break CI/CD pipelines
KubernetesCVE-2026-120307CVSS 9.9 · CRITICAL

Summary: The Beta9 worker serves the sandbox file API from outside the container. getHostPathFromContainerPath turns the tenant's container path into a worker path. If the unresolved path starts with a mount destination (including default upload mount at /tmp/.beta9), the remainder is joined onto that mount's source with filepath.Join, which cleans parent-directory segments after the prefix check. A long enough run of those segments names any absolute path on the worker. A path matching no mount is joined onto the container root and opened in the worker's own filesystem, allowing absolute symbolic links.

Affected Features / Interoperability: Sandbox file API, getHostPathFromContainerPath, worker filesystem. Downstream impacts include arbitrary file read/write on the worker host, breaking sandbox isolation.

Source: https://github.com/beam-cloud/beta9, https://github.com/beam-cloud/beta9/commit/a28bf12cf0007c792a25d8ed282b4e8bf6f30393, https://github.com/beam-cloud/beta9/pull/1897

Actions:

  • Fix: Upgrade Beta9 to a patched version (specific version not specified in data)
  • Workaround: Restrict file API access or disable sandbox file operations
  • Tradeoff: May break legitimate file operations within sandboxes

Affected Features / Interoperability: User applications, Ring 3 protection mechanisms. Downstream impacts include privilege boundary violations affecting confidentiality, integrity, and availability.

Source: https://intel.com/content/www/us/en/security-center/advisory/intel-sa-01460.html

Actions:

KubernetesCVE-2026-63121CVSS 6.3 · MEDIUM

Summary: Kubewarden policies' trusted-repos-policy compares an image's registry hostname against reject/allow lists case-sensitively even though DNS names are case-insensitive. An image with an uppercase or mixed-case registry hostname can miss a rejection rule for the equivalent lowercase host, so the admission policy accepts a resource whose container runtime pulls the same prohibited image. Only reject-list configuration is affected.

Affected Features / Interoperability: Kubewarden admission policy, container runtime image pulls. Downstream impacts include admission control bypass allowing prohibited images to be deployed.

Source: https://github.com/kubewarden/policies/commit/bc5597fcbbb0bc464b714ca7ff645c9743dea41b, https://github.com/kubewarden/policies/security/advisories/GHSA-8p62-9vh2-272p, https://github.com/kubewarden/policies/tree/trusted-repos-policy/v2.1.2

Actions:

  • Fix: Upgrade Kubewarden policies to v2.1.2 or later
  • Workaround: Normalize registry hostnames to lowercase before admission checks
  • Tradeoff: Requires policy configuration changes
KubernetesCVE-2026-62284UNSCORED

Summary: OSAC operator's console-proxy RemoteConfigResolver parses Kubernetes Secret kubeconfig data with clientcmd.RESTConfigFromKubeConfig without sanitizing the resulting rest.Config.
