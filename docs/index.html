Scoped Vulnerability Tracking

Cloud Security

The most urgent issue this cycle is CVE-2026-122310 in Kyverno (CVSS 9.9 CRITICAL), which allows a namespace-scoped user to escalate to cluster-admin by hiding path traversal sequences in a Policy's `urlPath` fragment or query. This directly compromises Kubernetes control-plane integrity and affects any cluster running Kyverno 1.19.1. No CISA KEV-confirmed exploits appear in today's formal vulnerability set, so the highest theoretical severity drives priority. Docker/PaaS tooling also carries multiple critical RCEs (Dokploy, Yuxi, Chartbrew, mailcow) that warrant immediate patching where deployed.

Formal Vulnerabilities

AWSCVE-2026-121686UNSCORED

Summary: FrodoBots EarthRover Mini+ firmware (version 6.2.4_6.2.5_0.614.0) accepts arbitrary shell commands via AWS IoT MQTT messages and executes them as root. Authentication relies solely on shared IoT credentials with no per-device verification, enabling fleet-wide unauthenticated remote code execution.

Affected Features / Interoperability: The firmware's MQTT command handler; downstream impact includes full device compromise, potential pivot to AWS IoT Core resources, and disruption of telemetry/control pipelines.

Source: https://github.com/frodobots-org, https://kb.cert.org/vuls/id/188754, https://www.frodobots.ai/

Actions:

  • Fix: Apply patched firmware version (vendor has not specified a version number in the advisory; monitor FrodoBots releases).
  • Workaround: Rotate and restrict IoT credentials, enforce network-level segmentation to limit MQTT broker exposure, and monitor for anomalous command payloads.
  • Tradeoff: Credential rotation may temporarily disrupt legitimate device management; network segmentation could break legitimate fleet orchestration.
Microsoft AzureCVE-2026-112337CVSS 3.7 · LOW

Summary: Wazuh 3.7.0 through 4.14.8 contains a server-side request forgery in the Azure wodle `get_graph_events()` function. The function follows `@odata.nextLink` pagination URLs without host or HTTPS validation, allowing an attacker who can influence the `nextLink` value to redirect manager requests to an attacker-controlled endpoint, capture the reused Microsoft Graph bearer token, and reach internal services.

Affected Features / Interoperability: Wazuh's Azure log collection wodle; downstream impact includes potential token theft and internal service enumeration via the Wazuh manager.

Source: https://github.com/wazuh/wazuh/releases/tag/v4.14.9, https://github.com/wazuh/wazuh/security/advisories/GHSA-qxg8-jrjm-w96h, https://www.vulncheck.com/advisories/wazuh-3.7.0-before-4.14.9-ssrf-via-azure-graph-nextlink-pagination

Actions:

  • Fix: Upgrade Wazuh to 4.14.9 or later.
  • Workaround: Disable the Azure wodle if not required, or restrict the manager's outbound network access to only required Microsoft Graph endpoints.
  • Tradeoff: Disabling the wodle loses Azure security event ingestion; network restrictions may break legitimate Graph API pagination.
KubernetesCVE-2026-122310CVSS 9.9 · CRITICAL

Summary: Kyverno 1.19.1 validates a Policy's `context.apiCall.urlPath` after cleaning it but executes the raw path. A namespace-scoped user who can create a Policy can hide `../` segments behind a fragment (`#`) or query (`?`) to reach cluster-scoped endpoints using Kyverno's ServiceAccount, achieving cluster-admin privileges.

Affected Features / Interoperability: Kyverno's policy engine `apiCall` mechanism; downstream impact includes full cluster compromise via the Kyverno controller's elevated ServiceAccount.

Source: https://github.com/kyverno/kyverno/security/advisories/GHSA-3xfv-vq8x-qhg4, https://www.vulncheck.com/advisories/kyverno-1.19.1-before-1.19.2-privilege-escalation-via-policy-apicall-urlpath

Actions:

  • Fix: Upgrade Kyverno to 1.19.2 or later.
  • Workaround: Restrict Policy creation permissions (RBAC) to trusted administrators only; avoid running Kyverno with a cluster-admin ServiceAccount if possible.
  • Tradeoff: Restricting Policy creation may hinder GitOps workflows; reducing Kyverno's ServiceAccount privileges could break legitimate policy enforcement.
KubernetesCVE-2026-102340CVSS 8.5 · HIGH

Summary: Telepresence before 2.31.0 exposes an unauthenticated gRPC API on port 8081. The `ArriveAsClient` RPC stores a caller-supplied namespace using only a manager watchlist check, and `CreateIntercept` can target any managed namespace without verifying the session's Kubernetes RBAC. Any pod with network access to the Traffic Manager can register in an arbitrary managed namespace, create service intercepts, receive intercepted traffic, and obtain the victim pod's credentials.

Affected Features / Interoperability: Telepresence Traffic Manager's gRPC API; downstream impact includes traffic interception, credential theft, and lateral movement within the cluster.

Source: https://github.com/telepresenceio/telepresence/commit/04ec3464fe8878fdc96420cdc8036edefa0dc9ae, https://github.com/telepresenceio/telepresence/commit/36458b65a010d2b316af48cd90e193ba190785d9, https://github.com/telepresenceio/telepresence/commit/6871235b674a6e843908d09696354c4b0f91578c

Actions:

  • Fix: Upgrade Telepresence to 2.31.0 or later.
  • Workaround: Block network access to the Traffic Manager's port 8081 from untrusted pods using NetworkPolicies; run the Traffic Manager in a dedicated, isolated namespace.
  • Tradeoff: NetworkPolicies may interfere with legitimate development workflows; isolation adds operational overhead.
KubernetesCVE-2026-102339CVSS 8.2 · HIGH

Summary: Telepresence before 2.31.0 parses a session ID from the first bytes of a caller-controlled message in the Tunnel gRPC streaming endpoint and passes it to `state.Tunnel` without verifying ownership. An attacker who obtains a valid active session ID (via log leakage, cluster-internal channels, or the unauthenticated `ArriveAsClient` endpoint) can attach a routed tunnel to that session and gain its network routing capabilities.

Affected Features / Interoperability: Telepresence Tunnel gRPC endpoint; downstream impact includes session hijacking and unauthorized network routing.

Source: https://github.com/telepresenceio/telepresence/commit/1312482488b771742dbedd3015f9a81a27532de6, https://github.com/telepresenceio/telepresence/commit/36458b65a010d2b316af48cd90e193ba190785d9, https://github.com/telepresenceio/telepresence/pull/4217

Actions:

  • Fix: Upgrade Telepresence to 2.31.0 or later.
  • Workaround: Same as CVE-2026-102340 — restrict Traffic Manager network exposure and monitor logs for session ID leakage.
  • Tradeoff: No significant tradeoff beyond the network restriction mentioned above.
KubernetesCVE-2026-66297CVSS 8.0 · HIGH

Summary: Livebook (livebook-dev) allows OS command injection into generated deployment setup commands. The `docker_instructions/2` and `fly_instructions/4` functions interpolate deployment group environment variable values into Docker and Fly.io setup commands without shell escaping.
